# 私有扩展示例

本页演示如何在框架仓库之外安装一个私有基线 runner，并把其 unittest 模块接入框架测试入口。示例只做加法，数据、包名和结果都是合成的；它不包含真实模型、测点、工厂或公司数据，也不能作为模型验收证据。

## 安装并运行合成示例

在框架仓库根目录，把固定 Python 3.11 环境的解释器路径赋给 `$Python`。本仓库初始化环境默认位于 `.venv-311`。先把 fixture 复制到仓库之外，再将本地包安装到该框架环境；构建依赖若需下载，按入口 04 设置自己的 HTTP 代理，不覆盖他人的本机端口：

```powershell
$Python = (Resolve-Path ".\.venv-311\Scripts\python.exe").Path
$PrivatePackage = Join-Path $env:TEMP ("synthetic-private-extension-" + [Guid]::NewGuid().ToString("N"))
Copy-Item -Recurse -LiteralPath ".\tests\fixtures\private-extension" -Destination $PrivatePackage

uv pip install --python $Python --no-deps $PrivatePackage
$env:MODEL_LAB_PRIVATE_TEST_MODULE = "synthetic_private_baseline.tests"
& $Python -I -m unittest $env:MODEL_LAB_PRIVATE_TEST_MODULE
```

安装步骤使用固定解释器；测试命令中的 `-I` 让 Python 忽略当前目录和 `PYTHONPATH`，从已安装包及框架环境导入代码。此模块会从包内读取独立保存的输入与期望 JSON，检查正常回放、错误期望值和无效输入。完成演示后，可卸载合成包：

```powershell
uv pip uninstall --python $Python synthetic-private-baseline-example
```

## 接入框架测试档

入口点由 `pyproject.toml` 的 `model_lab.baseline_runners` 声明；runner 返回框架的 `BaselineRunner`，并实现 `replay(input_document, expected_document)`。回放遇到未知形状、非有限数字、用例数量不一致或结果不符时，必须返回 `BaselineProblem`，不能把问题降级成通过。扩展还声明输入、输出契约，框架会在验证时逐项比对。

私有 unittest 模块通过 `MODEL_LAB_PRIVATE_TEST_MODULE` 指定模块名，例如合成演示中的 `synthetic_private_baseline.tests`。真实模型应把自己的测试模块放在外部私有工作区中，并确保固定框架环境能按该模块名导入。示例包只是安装和导入方式的演示：`test-profile linux-offline` 仍要求经核验的公司归档及真实私有测试模块；`linux-online` 还要求明确的在线 opt-in 和近期 smoke 起始时间。不要用合成包、虚构归档或本机 unittest 结果代替这些门禁。
