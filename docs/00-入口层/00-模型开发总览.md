# 模型开发入口

首次使用按 [人工操作快速开始](04-人工操作快速开始.md) 运行一次本机初始化，使用固定框架命令入口。同事默认拉取 `main`；每次拉取后由初始化助手更新依赖和技能，复用本机配置。实际框架来源用 `doctor` 查询，不凭解释器路径或相同版本字符串猜测。

先明确任务是新模型、已有模型维护、数据审查、验证构建，还是发布。阅读 [分流矩阵](03-模型任务分流与加载矩阵.md)；会修改文件时再读 [交互档位](06-模型任务问答与交互档位.md)。不要先遍历全部模型或默认读取公司数据。

真实模型必须使用本仓库外的私有目录。初始化会保存本机目录，也可设置 `MODEL_LAB_MODELS_ROOT` 或在新建时传 `--models-root`。已经知道具体工作区时，运行 `model-lab context <工作区> --task status` 与 `model-lab status <工作区>`，再读它指出的最小文档、`model.yaml` 和证据。若版本不唯一，只问一次模型 ID 与版本。

通用流程是：需求确认 → 草稿契约 → 数据审查 → 构建验证 → 目标运行时预检 → 指定实验上传与回载。阶段门禁由 `status/advance` 判断；模板和通用测试不能证明实际模型已上线。`model-lab doctor` 先检查 Python 3.11；`release-gate` 只检查本框架仓库的隐私与 Git 历史。

本仓库的 Codex hook 只读、可不用；恢复入口始终是 `AGENTS.md` 与本页。状态快照和 hook 详见 [状态说明](07-模型状态快照与Hook.md)。
