## 命令与边界

首次使用按 README，在干净克隆的 Windows 上执行 `scripts/bootstrap.ps1 -ModelsRoot <外部临时目录>`；Linux 执行 `bash scripts/bootstrap.sh --models-root <外部临时目录>`。后续统一使用固定 launcher，不依赖终端激活或当前目录中的旧模块。

完整本机回归用 `test-profile local --format json`；仓库隐私检查用 `release-gate --format json`。公网依赖安装显式使用验证机器的 HTTP 代理环境变量，未关闭代理、VPN 或修改路由。

新手反馈已对齐说明：`new --apply` 只生成待完善草稿，不代表需求已确认、模型已建成或已上传；下一步看 `status` 的真实缺项。测试退出 0 不必然是零跳过通过，仍要看 `status`、`complete` 和跳过原因。

Linux 未提供公司 ZIP 和私有模型测试模块时，实际 `test-profile linux-offline` 返回 `blocked`、0 执行、退出 1，列出这两个真实缺项；这不是通用框架初始化的授权门禁，也不是公司部署通过。本轮未导入公司模块、调用真实 IoT 或上传模型。

手工后备步骤已交付；未单独做没有 uv 的依赖安装端到端演练。客户端 hook 信任未验证。已发布测点 `serving` 模型的自动维护分叉及 GPU/Chronos 专用构建仍不在已实现能力内，人工快速开始明确说明，不能用这份框架验收绕过。
