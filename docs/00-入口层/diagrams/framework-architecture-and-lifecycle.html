Framework Architecture · Water Model Governance

通用水务模型开发框架全景架构与生命周期确认门禁流

展示水务算法模型工程治理通用体系：Windows 本地开发控制面与 Linux 容器生产实包严格解耦， 全生命周期六阶段标准递进，由四大自动化硬门禁与双轴代码审查构筑确定性防护网，严禁未授权或越权发布。

SECTION 01 · SYSTEM TOPOLOGY

双运行时解耦与质量门禁全景架构拓扑

Windows 本地控制面（代码、契约、探索）与 WSL Linux 目标平台（PyArmor、MLflow 实包、离线推理）分离运行，并通过四道自动化硬门禁与双轴审查构筑确定性防线。

SECTION 02 · GENERAL LIFECYCLE PIPELINE & CONFIRMATIONS

通用全生命周期六阶段递进流与各步骤确认门禁

展示适用于各类水务算法模型（加药模型、曝气模型、水力延时模型、出水预测模型等）的标准生命周期流程。在完成前序 4 个阶段（环境自检、需求设计、研发验证、实包构建）的全部决策确认与实包推理验证后，模型正式达成可发布（releasable）里程碑状态。

SECTION 03 · STEP CONFIRMATION MATRIX

各步骤通用确认项、检查清单与交付物总览

明确框架下每个生命周期阶段由谁负责、必须确认的通用标准项、输出证据文件，以及推进至下一阶段必须满足的硬性前置条件。

全流程工程治理闭环

RUNTIME ISOLATION

双运行时完全解耦

彻底解决 Windows 本地开发环境与云端 Linux 生产环境差异引发的上线即报错痛点：

  • 控制面 (Windows)：通过 model-lab 进行脚手架生成、契约定义与数据探索。
  • 执行面 (Linux WSL)：独立隔离构建 release-bundle/service 部署实包，并在 Linux Python 3.11 环境运行 loaded.predict() 离线冒烟。

QUALITY ASSURANCE

四道硬门禁确定性拦截

在任何模型合并或发布前，必须 100% 自动化通过四道不可绕过的质量闸门：

  • Gate 1 (doctor)：Python 3.11 环境基线与依赖诊断；
  • Gate 2 (catalog)：中央资产目录与所有在役模型无漂移；
  • Gate 3 (context)：全量模型上下文快照一致性核验；
  • Gate 4 (release-gate)：8 项发布规则与敏感文件全面拦截。

GOVERNANCE POLICY

人机握手与显式授权红线

杜绝越权上传与隐式破坏，保障水务工业模型上线资产安全与可追溯性：

  • Stage 0 前置握手：开局必须核验 Python 3.11、能力包 SHA256，完成固定问卷再编码；
  • 发布权限收口：禁止自动执行 publish --apply，必须获得用户单次显式授权并存档回执。

STAGE 0 · MUST CONFIRM

基建自检与任务前置握手

开工首回合必须完成基建握手，禁止无环境盲跑：

  • 解释器与环境基线：Python >=3.11,<3.12 唯一受控；WSL Linux 3.11 容器就绪。
  • 任务与 Issue 载体形态：GitHub 远端 Issue (#ID) vs 本地 Markdown 离线规格。
  • 生命周期演进模式：新建全新模型 (0.1.0) / 缺陷补丁 (x.y.z+1) / 次版升级。
  • 专属技能与安全红线：按需识别授权 (diagram/water)；私有数据绝对禁止入 Git。

STAGE 1-2 · MUST CONFIRM

契约数据与算法路线固定必答

点位、时间步长与聚合口径必须固化写入 model.yaml：

  • 数据源策略与防偷懒门禁：动态拉取 (live-iot + 回执) vs 离线基准；杜绝本地文件偷懒。
  • 计算频率与调度周期：10 分钟中控标准 / 5 分钟敏捷调节 / 1 小时报表。
  • 多探头冗余聚合规则：双探头均值 (mean) / 极值 (max/min) / 单探头 / 主备回退。
  • 双速架构与依赖纯洁度：Windows 本地极速开发 (<0.1s) / WSL 按需发布保真预检。

STAGE 1-5 · DEEP DIALOGUE

现场工艺与极端工况开放探讨

探讨结论必须留档于 model-spec.md 与 decisions.yaml：

  • 探头故障与断流保底策略：结垢显示 0 / 负值时，前向保持 vs 历史均值 vs 物理截断兜底。
  • 冲击工况与参数分支切换：暴雨雨季大水量 / 低温冬季工况下的算法常数动态调整。
  • 离线验证样本与精度要求：单条冒烟 vs 24h (48~144点) 连续回放；绝对误差 vs 统计 MAPE。
  • 线上安全告警与故障回滚：重点指标监控 (DO/氨氮)；异常时切回传统 PLC 人工设定值。
