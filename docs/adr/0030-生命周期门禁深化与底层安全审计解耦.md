# 生命周期门禁深化与底层安全审计解耦

状态：已接受（2026-10-13）

## 背景与决定

在框架演进过程中，`model_lab/lifecycle.py`（1640L）与 `model_lab/release_gate.py`（1716L）逐渐演变为承担过多职责的浅宽模块：
1. **内部细节泄露与反向依赖**：`lifecycle.py` 为了校验工作区文件安全性，越过模块缝隙直接依赖 `release_gate.py` 的内部函数 `scan_workspace_tree`；而 `release_gate.py` 作为发布验收与仓库治理的顶层编排器，反向被状态机底层依赖，产生了概念上的倒置与循环穿透。
2. **正交逻辑杂糅**：`lifecycle.py` 内部硬编码了 400 行编译器前端性质的 Python 与 Jupyter Notebook 静态语法树（AST）可达性与空实现分析（`_statement_flow`、`_ModuleBindingFinder` 等）；`release_gate.py` 同样将底层的 Git 裸对象流提取（`cat-file`）与字节级正则扫描和高层的 9 个在役模型盘点、基线回放混在同一文件。
3. **加载器碎片化重复**：防 YAML 键名歧义的 `_UniqueKeySafeLoader` 在 `manifest.py`、`decisions.py`、`runtime_contract.py` 中被重复实现 3 次。

决定：实施“底座解耦 + 核心深化”重构，将浅模块改造为深模块（高杠杆、窄接口、内聚实现）：

1. **底层静态安全审计独立为专用模块 (`model_lab/security_audit.py`)**。
   将工作区目录树遍历、软链接/连接点判定、秘钥/大文件/原生二进制正则过滤以及 Git 历史裸对象批处理扫描完全封装在安全审计模块中。向外暴露极窄的 `audit_workspace_tree(path) -> tuple[SecurityIssue, ...]` 与 `audit_git_history(repo_root) -> HistoryAuditReport` 接口。`lifecycle.py` 与 `release_gate.py` 均作为调用方消费该接口，彻底消除 `lifecycle` 对 `release_gate` 的反向依赖。
2. **代码静态就绪度检验沉淀为专用分析器 (`model_lab/ast_guard.py`)**。
   将 Python 语法树到达流分析、异常抛出判断、函数实现有效性与 Notebook 单元格扫描从生命周期主流程中剥离，封装为独立的 `ast_guard` 模块，提供 `inspect_python_readiness` 与 `inspect_notebook_readiness` 窄接口。
3. **生命周期门禁引擎深化为高内聚控制面 (`model_lab/lifecycle.py`)**。
   生命周期模块专注于模型生命周期的状态跃迁逻辑与声明式原子文件事务（`claim` / `rollback` / `atomic_write`），门禁规则通过统一缝隙调度子检查器。外部调用方（CLI、自动化任务智能体）仅面对 `workspace_status` 和 `advance_workspace` 两个原子契约。
4. **统一安全文档加载基础设施 (`model_lab/document_loader.py`)**。
   消除跨模块重复的 SafeLoader 实现，统一约束 YAML 唯一键与 UTF-8 编码要求。

## 边界

- **不改变既有门禁判定规则**：所有的安全规则（10MB 上限、密钥正则、禁止软链接、PyArmor 运行库放行等）和 AST 判定条件（NotImplementedError 拦截、pass 空函数拦截等）保持严格逐位兼容，不放宽也不额外收紧任何硬性门禁。
- **不破坏原子写盘与安全回滚**：工作区推进时的 `claim` 临时锁定、清单指纹校验与回滚机制完整保留并内聚在生命周期事务管理器内部，严禁退化为无保护的原地覆盖。
- **不改变外部 CLI 契约**：`model-lab status`、`model-lab advance`、`model-lab release-gate` 命令参数与输出 JSON 格式保持 100% 向后兼容。

## 后果

- 消除 `lifecycle.py` 与 `release_gate.py` 之间的反向模块泄露，形成单向清晰的依赖分层：`cli` -> `lifecycle` / `release_gate` -> `ast_guard` / `security_audit` -> `document_loader` / `path_safety`。
- `lifecycle.py` 复杂度与行数显著缩减，AST 静态分析与安全文件扫描具备了独立的纯函数级单测能力。
- 模块深度（Depth）大幅增加，开发者与协作智能体在维护生命周期状态流转时拥有了极高的局部性（Locality）。
