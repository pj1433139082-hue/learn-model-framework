# 固定实包发布替代全局禁用

状态：已接受（2026-09-28）

## 背景

早期 `model-lab publish` 即使目标、实验、作者和用户授权齐全，也固定返回
`publish_backend_disabled`。这是仓库自身的阶段性保护，不是公司要求再次审批。
公司能力包已有 MLflow 连接能力，但其 `run_pipeline_and_deploy` 会重新构建模型，
不能据此证明上传的是已验收的固定实包。

## 决策

保留 ADR 0004/0012 的限定事务授权；一次明确指定模型版本与实验的上传指令
不再重复确认。`publish` 默认只读预览，只有显式 `--apply` 才调用远端适配器。
首个适配器仅覆盖具备在线验收收据的 CPU-IoT 测点模型；从已验证的 `model.yaml`
取得目标与实包摘要，在目标 Linux Python 3.11 环境核对公司 ZIP 摘要，复用其
连接初始化，把现有 `release-bundle/service` 原样记录到公司约定的 `service`
路径。上传后回下载并核对字节树摘要，再以平台路径加载和预测；失败 Run 不得
记为 released，不自动调度，也不替换旧版本。其他目标与验收档仍明确不支持。

网络不可达是技术阻塞，不是新增授权要求。发布者只提供已知的实验名与作者标识；
公司 ZIP 路径、Python ABI、制品摘要及连接参数由执行环境和框架核验，不向用户
索取密钥。早期文档中“全局发布后端禁用”“须公司另行批准接口”的表述由本决策
取代；真实平台成功仍以 Run ID、远端实包摘要及预测回执为准。
