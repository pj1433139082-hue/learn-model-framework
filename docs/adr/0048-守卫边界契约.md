# 0048 守卫边界契约：提示不是门禁，白名单与后缀是唯一判据

> 本 ADR 保留私有源仓原文；`step-check`、`ledger`、`.dsh-hooks` 在本公开框架分发仓未实现，请以 `status`、`context`、`.codex/hooks.json` 为准。

- 状态：已接受
- 日期：2026-10-20

## 背景

仓库里有两种"拦住你"的机制，长期被当成同一回事：

1. `.dsh-hooks/settings.json` 的守卫（hooks-kit 执行）：在工具调用**之前**按路径与后缀拦截；
2. `model-lab` 的确定性门禁（`step-check`、`release-gate` 等）：在工具调用**之后**按状态给结论和退出码。

两者只共享一份口径（仓库根常驻文件清单，见 ADR 0047），却不共享行为。把守卫当门禁的实际后果是：
有人为跑通一条只读命令去改 `settings.json`，也有人以为"守卫放行了就等于产物合规"。

本轮实测到一次典型误判：统计草稿目录数量的只读命令
`(Get-ChildItem -Directory models/_drafts | Measure-Object).Count` 被拦，理由是
"仓库根新建文件（命中 workspace-root:E:\beikong-code\learn-model\Measure-Object).Count）"；
命令文本里出现仓库根文件名（如 `README.md`、`SKILL.md`）或 `@{n=...}` 这类拼接也会同样误判。

守卫因此需要一份写下来的边界：它拦什么、不拦什么、拦错了怎么办。

## 决策

1. **守卫只有一条判据：`guard.workspaceRoot` 的路径策略**——把候选路径解析成绝对路径，
   判「仓库根直接子级 + 文件名不在白名单（8 项，对齐 `RESIDENT_ROOT_FILES`）+ 命中可疑后缀」。
   `guard.extraDeny` 自 2026-10-20 起为空数组（原文见文末修订）。它不读文件内容、
   不判生命周期状态、不判发布回执。
2. **守卫不参与任何退出码**：`model-lab` 的退出码只由命令自己给（口径见
   `docs/00-入口层/02-v0.1.0兼容与迁移说明.md`）。守卫发生在工具调用之前，既不产生
   也不吞掉任何命令的退出码；命令行层的唯一判定仍是 `step-check` 输出里的
   「仓库根越界产物」行。
3. **`ask=true` + `allow=[]` 的语义是"没有预授权、命中即拦"**，不是"允许"。放行只有两个
   人工动作：把关键片段加进 `guard.allow`，或临时把 `guard.enabled` 设为 `false`；
   两者都是纪律变更，必须记账，不得为单条命令悄悄加白。
4. **误判的处理方式是绕过，不是放宽**：改用 `read` / `grep` / `write` / `edit` 工具，
   或把脚本落到 `%TEMP%` 再执行；不为被误拦的只读命令改判据。
5. **守卫不改变任何生命周期门禁**：技能负责对话、`model-lab` 负责确定性门禁的双层结构
   （ADR 0010）不变；人机前置握手里的 Hook 自检（ADR 0024）只确认 Hook 已就位，
   握手结论同样不进退出码。
6. **口径对照与已知限制只记在 `.dsh-hooks/README.md`**：`settings.json` 是 JSON，写不了注释，
   所以"键 → 唯一来源 → 同源断言"的对照表与守卫的失效模式都在那份 README 里；本 ADR 只记边界，
   ADR 0047 只记白名单单一来源，三者不互相复制判据。

## 后果

- 越界判定重新统一到 `step-check`：被守卫拦下的提示可以在换用工具后完成同一件工作，
  不必修改判据；真正合规与否看 `step-check` 的输出与退出码。
- `settings.json` 的每次改动都要带一句理由（为什么放开/收紧），并同步 `.dsh-hooks/README.md`
  的对照表，避免"改了配置没人知道为什么"。
- **已知限制（与 `.dsh-hooks/README.md`「已知限制」同源，此处只列结论）**：
  - 守卫只挂 `pwsh`、`write`、`edit`、`read` 四个工具；`run_code` 里的文件操作、外部编辑器
    与 WSL 不经过它，所以它给不出"全局合规"的保证。
  - 路径策略实现在 hooks-kit 插件里（不在本仓），可疑后缀集是插件默认值，与
    `root_discipline.STRAY_SUFFIXES` 是两份：守卫多算 `.json` / `.zip`，本仓改不动。
  - `workspaceRoot.allow` 是 JSON 字面量，需人工同步；由
    `tests/test_repository_layout.py` 断言与 `RESIDENT_ROOT_FILES` 集合相等。
  - 仓库根的 `.json` 也在插件可疑后缀里，包括被 Git 忽略的 `.model-lab.local.json`：直读会被拦，
    只能走 `model_lab setup --format json` 回显（详见 `.dsh-hooks/README.md` 已知限制 6）。
- 代价：被误判时多一步绕行（换工具或落临时脚本）；换来的是"守卫不是门禁"这条稳定预期，
  避免为跑命令反复改安全配置。

## 被否决的方案

- **让守卫兼任门禁（命中即判失败、影响退出码）**：守卫看不到模型状态与发布回执，判不了合规，
  只会把"路径像越界"当成"产物越界"，产生第三套漂移判据。
- **给每条被误拦的命令往 `guard.allow` 加例外**：白名单会退化成命令白名单，判据被稀释且无人审；
  误判的根因是路径像越界（守卫只看形状、不看内容），不是名单不够长。
- **把 `ask` 改成 `false` 或默认关闭守卫**：越界文件会在写入时就落盘，只剩事后被动发现，
  "先拦住再解释"的价值消失。
- **让守卫按文件内容判定是否越界**：每次工具调用前读全部写入内容，成本高于收益
  （与 ADR 0047 的否决理由一致）。

## 2026-10-20 修订：退役 `extraDeny`

- **原判据**：`guard.extraDeny` 里一条正则，形如
  `[\\/]learn-model[\\/]+(?!README\.md$…)[^\\/]+\.(md|ipynb|csv|xlsx|pkl)$`，
  对 `pwsh` 命令文本或文件路径的**原始字符串**做匹配。
- **退役理由**：① 它把仓库目录名写死成 `learn-model`，克隆改名后静默失效；② 它按原文匹配，
  分不开「仓库根的新文件」和「工作区里的嵌套路径」，只能靠否定前瞻补救，误拦率高；③ 自
  `workspaceRoot` 路径策略落地后，两者判的是同一件事，保留它只会产生第二份会漂移的判据。
- **改法**：`.dsh-hooks/settings.json` 的 `guard.extraDeny` 改为 `[]`；`model_lab/setup.py`
  的 hooks 自检把 `workspaceRoot.allow` 条数也计入判据（新增 `guard_root_rules`），
  `guard_enabled` 仍为真。`.dsh-hooks/README.md`、ADR 0047 的对应条目同步改写。
- **代价与边界**：守卫从此只看绝对路径；命令文本里只提到文件名、而实际由程序内部写盘的场景
  本来就不经过守卫，边界不变。真正判定仍是 `step-check` 的「仓库根越界产物」行。
