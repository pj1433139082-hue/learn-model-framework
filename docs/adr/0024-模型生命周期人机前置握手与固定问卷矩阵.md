# 模型生命周期人机前置握手与固定问卷矩阵

状态：已接受（2026-10-12）

## 背景

在模型研发实践中，开发者或智能体在面对新任务时常存在两种极端：
1. **随意假设与过度发散**：未核实关键输入（如数据来源、点位聚合口径、依赖纯洁度、实验标识）就仓促编码，导致后期返工与平台不兼容；
2. **缺乏结构化沟通标准**：每次开工向用户提问的内容临时拼凑、层次不清，将标准技术参数（如 Issue 载体、时序步长、探头聚合规则）与需要深度的现场工艺探讨（如异常保底截断、暴雨工况切换）混为一谈。

为了建立确定性的人机协作边界，必须将各阶段的沟通明确划分为**“固定问卷（标准化单选/必填项）”**与**“非固定开放探讨（工艺/现场策略）”**，并在开局（Stage 0）前置落实环境、技能与安全 Hook 的自检握手。

## 决策

1. **确立生命周期两级沟通模型（固定问卷 vs 开放探讨）**：
   - **固定必答项**：针对已标准化的工程边界（Issue 载体、版本生命周期模式、实验标识与 Owner、数据形态 Excel/Point-Codes、计算周期 10min/5min、探头聚合均值/极值/主备、算法路线机理/机器学习/深度时序、离线比对基准、依赖纯洁度），提供有限枚举单选与必填字段，通过问卷式交互快速收敛；
   - **开放探讨项**：针对现场工艺痛点、复杂异常断流保底、极端工况参数分支、现场告警指标等非标准物理现实，展开深度探讨并在规格书（`model-spec.md`）和决策记录（`decisions.yaml`）中留档。

2. **Stage 0 开局实施工程基建与工具链前置握手（Stage 0 Handshake）**：
   - **环境自检**：通过 `model-lab-setup` 完成控制面 Python 3.11、WSL 生产环境与集团能力包哈希的三维只读探测；
   - **技能对齐**：主动识别任务所需专属技能（如 `diagram-design` 架构图、`water-quality-experiment` 水质时序），提示并单次授权同步；
   - **安全底线与 Hook 确认**：声明 Git 守卫、禁用 `git rm`、私有数据严禁入 Git 及逐次授权推送等核心红线。

3. **双轨固化与交付约束**：
   - 在规程文档 `docs/00-入口层/08-框架全景流程与发布核对清单.md` 中固化完整问卷模版；
   - 在架构与流程矢量图（`framework-lifecycle-confirmations.svg`）及交互单页中增加人机确认与固定问卷导航矩阵；
   - 在项目技能（如 `model-requirements-grill` 与 `model-lab-setup`）中将其作为前置检查规则，杜绝未经确认的隐式假设。

## 影响

- **收益**：新模型或维护任务开工前 5 分钟内即可收敛 100% 的技术边界与环境就绪度，彻底消除因数据格式、点位口径或平台差异导致的返工。
- **约束**：开发者与智能体必须严格遵循前置握手流程，严禁在未确认固定输入的前提下直接跳步编写业务代码。
