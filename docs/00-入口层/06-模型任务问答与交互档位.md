# 交互档位与问答

首次可变更任务提供一次 `full-auto`、`assisted`（推荐）、`manual-review` 选择；未答复时按 `assisted` 继续已授权的本地任务，不把沉默当成发布授权。只读诊断不需选档。恢复同一任务不重复问。

| 场景 | 自动取得的事实 | 只需询问的业务选择 |
| --- | --- | --- |
| 新模型 | 已有文件、可用数据、运行环境 | 目标、公式、入输出、边界、验收标准 |
| 行为不变维护 | 旧 Run 签名、版本、固定输入基线 | 只有证据冲突或基线不明时问 |
| 契约/算法升级 | 父版本与差异 | 变化的字段、时间策略、行为及标准 |
| 数据审查 | 时段、缺失、异常、单位统计 | 排除、填补或容忍的业务口径 |
| 构建验证 | 测试、指标、图表、制品摘要 | 接受偏差或冻结结论 |
| 指定发布 | 已给实验名/编号和作者、包与环境事实 | 仅真正缺失的业务信息，不重复确认同一次上传 |

独立问题合并提问，每题给推荐与备选；“按推荐”只确认实际已展示的那批决定。`model.yaml` 记录事实，`decisions.yaml` 记录答案。`full-auto` 不绕过门禁；`manual-review` 才逐项暂停。Git 远端和平台上传须有覆盖具体目标的用户指令，且上传不自动包含生产调度。
