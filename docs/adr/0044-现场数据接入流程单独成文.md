# 0044 现场数据接入流程单独成文，产物按数据/脚本/证据三分

- 状态：已接受
- 日期：2026-10-17

## 背景

某厂风机效率核算这条链路上，从「甲方台账 → 点表 → 拉数 → 清洗 → 出图 → 分析报告 → 对外清单」的每一步都实际走通了，
但知识是散落的：台账在桌面文件夹、取数方法在会话里、清洗规则在某个模型的 `decisions.yaml`、
出图与对外清单的形态只存在于这一个模型的 `docs/`。下一次做别的模型要重新踩同样的坑。

同时踩到三个真实缺陷，都是「放错地方」导致的：

1. 原始 parquet 放在模型工作区 → `workspace-safe` 门禁判 31 项失败（`model_lab/security_audit.py` 禁止工作区内出现原始数据文件）；
2. 台账从桌面就地读取 → 违反 `docs/20-规则层/30-模型-水厂数据集映射.md` 已有的 `data/台账/` 约定，且文件不在仓库内、无哈希可核；
3. 出图把辅助信号一起画、y 轴不裁剪 → 坏值块把正常工况压成平线，图集等于无效。

## 决策

1. **该链路单独成文**：`docs/10-流程层/26-现场数据接入流程.md` 是「台账→点表→取数→数据质量→分析报告→对外清单」的唯一流程文档；
   `11-新模型开发SOP.md` 的 ③④ 只加指针，不复制内容。
2. **产物三分**：
   - 原始数据（台账、填报模板、parquet、中间聚合表）→ 仓库级 `data/`，被 `.gitignore` 忽略；
   - 方法与脚本（点表生成、批量取数、出图）→ `scripts/取数探针/`，通用、可复用；
   - 证据与结论（分析报告、数据质量结论、对外清单）→ 模型工作区 `docs/`、`plots/`、`work/analysis/`，进 git。
3. **点表由脚本从台账生成**，不允许手抄。测点 ID 少写尾缀时接口静默返回空值，
   手抄 6 台 × 17 信号 = 102 个 ID 必然出错，且错法表现为「没数据」而不是报错。
4. **出图默认裁 y 轴**（分位数裁剪）并只画参与计算的信号；全量程视图需要显式传参。
5. **对外清单按收件人拆成完整独立文案**：发给现场的那一段就是对方能看到的全部内容，摘要式清单必然漏回。

## 后果

- 下一个模型做现场数据接入时不必重新试错，直接照流程文档走；
- 原始数据永远不在工作区，`workspace-safe` 门禁与 `.gitignore` 两条约束同时成立；
- 代价：多一个 `docs/10-流程层/26` 文档要维护。若流程变更，SOP ③④ 的指针不需要改，
  但本文必须同步，否则文档与脚本会分叉。

## 被否决的方案

- **把内容全部塞进 SOP ③④**：SOP 是九步执行清单，写进上百行操作细节后不再可读，
  且 SOP 的改动影响所有模型任务。
- **作为某个模型工作区的附录**：这只对当前模型成立，换模型就失效；
  但反过来说，模型特有的口径（本例是 Excel 与修正双口径）仍然留在工作区，本文只承载通用链路。
- **建独立的数据分析报告模板文件**：报告骨架只有九节，写进流程文档即可；
  单独建模板会立刻分叉（模板改了文档不改）。骨架内嵌在 26 的 §8。
- **把出图的 y 轴裁剪做成默认关闭的选项**：默认关闭等于没人用，坏值块会持续污染图集。
