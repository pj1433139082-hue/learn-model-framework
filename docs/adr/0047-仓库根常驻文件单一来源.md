# 0047 仓库根常驻文件单一来源：RESIDENT_ROOT_FILES

- 状态：已接受
- 日期：2026-10-20

## 背景

"仓库根只放哪几个文件"这条规则此前有**三份各自漂移的副本**：

1. `model_lab/root_discipline.py` 的 `ALLOWED_ROOT_FILES`：五项，含从未存在过的 `LICENSE`，
   却不含 `pyproject.toml` / `.python-version` / `.gitignore` / `.gitattributes`；
2. `.dsh-hooks/settings.json` 的 `guard.workspaceRoot.allow`：九项，同样列着 `LICENSE`，
   却把上面四个常驻文件都列进了白名单；
3. `AGENTS.md` 与 `CONTEXT.md` 里的文字复述（"仓库根只放五个文件"）：写死文件名，
   与机器判据不同步。

漂移的实际表现是：守卫放行 `LICENSE`（磁盘上根本没有这个文件），而 `step-check` 会把
守卫允许的 `pyproject.toml` 当越界产物；同一份"根级文件名清单"在机器判据与文字说明里
给出不同答案，读者无法判断哪一份才算数。

## 决策

1. **`RESIDENT_ROOT_FILES` 是仓库根常驻文件的唯一清单**：`AGENTS.md`、`CHANGELOG.md`、
   `CONTEXT.md`、`README.md`、`pyproject.toml`、`.python-version`、`.gitignore`、
   `.gitattributes`（八项，均为磁盘实际存在的文件；`LICENSE` 退役）。
2. **`ALLOWED_ROOT_FILES` 保留为同对象别名**（`ALLOWED_ROOT_FILES = RESIDENT_ROOT_FILES`）：
   `step_check` / `project_context` / `cli` 已按旧名导入，且 `tests/test_step_check.py`
   断言两者是同一对象；新增消费方一律用新名，不新增第二份字面量。
3. **守卫白名单由它对齐**：`.dsh-hooks/settings.json` 的 `guard.workspaceRoot.allow`
   必须与 `RESIDENT_ROOT_FILES` 逐项相同，由 `tests/test_repository_layout.py` 断言集合相等，
   并同时断言清单里每个文件真实存在——两端任何一侧漂移都会当场失败。
4. **文字说明改为指向清单**：`AGENTS.md` 与 `CONTEXT.md` 不再复述文件名，
   改成"唯一清单是 `RESIDENT_ROOT_FILES`"；每轮提示块仍由该清单拼出，读的是同一对象。
5. **`extraDeny` 去重**：原第 2 条是第 1 条末尾多几组引号的子集（并存时只有第 1 条会命中），
   删掉冗余副本，并同时删掉否定前瞻里已死的 `LICENSE$`。
   （2026-10-20 补：该条此后被整体清空为 `[]`，根判定只剩 `workspaceRoot` 的路径策略，
   理由与后果记在 ADR 0048 的修订里；本 ADR 的"白名单单一来源"结论不受影响。）

## 后果

- 增删一个常驻文件只改 `root_discipline.py` 与 `settings.json` 两处；两处不一致会被测试拦下，
  不再出现"守卫允许但 `step-check` 判越界"的文件。
- `ARCHIVED_GENERATION_PATHS` 同步剔除两条已改名的旧路径
  （`docs/10-流程层/11-学习笔记-部署流程.md`、`docs/10-流程层/12-deploy脚本模板.md`），
  只保留真正"应缺席"的三项；测试断言该清单每条路径都必须不存在，清单不再是随便登记的历史名单。
- **已知限制（`settings.json` 不能写注释，只能记在这里）**：
  - `extraDeny` 曾把目录名硬编码为 `learn-model`；2026-10-20 已把该条清空为 `[]`，
    守卫不再依赖目录名，克隆改名后仍生效（见 ADR 0048 的"2026-10-20 修订"）。
  - 后缀口径在 hooks-kit 插件的默认集里，与 `root_discipline.STRAY_SUFFIXES` 是两份，
    且插件那份更宽（多算 `.json` / `.zip`）：新增一种根级裸产物类型（如 `.png`）时
    本仓清单要改，插件那份改不动；两份不一致只会让守卫更早提醒，不会漏过 `step-check`。
  - `workspaceRoot` 只校验文件名，不校验内容；它防的是"根级多出文档或数据文件"，不是内容审查。
- 代价：仓库根新增一个合理的常驻文件（例如将来的 `Makefile`）必须同时改清单与守卫白名单；
  这是刻意的摩擦，避免根目录悄悄长东西。

## 被否决的方案

- **只改 `root_discipline`，不动 `settings.json`**：守卫继续放行 `LICENSE`、继续拦
  `pyproject.toml`，两套判据并存，正是本 ADR 要消掉的问题。
- **删掉 `ALLOWED_ROOT_FILES`、全面改用新名**：`step_check` / `project_context` / `cli`
  与既有测试都按旧名导入，改名的收益只是名字更准，代价是跨模块改动与一次对外契约变更。
- **让 `settings.json` 从 `root_discipline` 生成**：hooks 插件只读 JSON、不跑 Python，
  仍需一份落地副本；生成器只会把漂移延后到"忘了重新生成"。
- **保留 `extraDeny`、只把目录名改成通配符**：它跑的是原始命令文本，分不开"仓库根的新文件"
  与"工作区里的同名路径"，放宽目录名只会把嵌套路径一起误拦；路径判据已经覆盖根级场景，
  这条正则因此整体退役，而不是改写。
- **把 `extraDeny` 改成按内容判定而不是按路径正则**：内容判定要在每轮输入前对全部写入做扫描，
  成本高于收益。
