# 0052 步骤台账：status 只是声称，判据由 step-check 重算

- 状态：已接受
- 日期：2026-10-21

## 背景

跑偏不是执行者不努力，而是**状态里没有步骤**：

- `workflow-ledger` 之前，唯一带步骤信息的机器状态是 `workflow-state.json`（七个键：模型、版本、生命周期、流程名、更新时间、摘要）。
  它由 `new` / `advance` / `context --write` / `publish` / `recovery` 触发整份重写，
  一个跨几小时的步骤（数据拉取、模型验证）全程没有任何 checkpoint，中途换人只能靠读文档猜。
- 工作区里的 `CHECKLIST.md` 是人工叙述：实测 `models/_drafts/fan-efficiency-zaozhuang-beikong/CHECKLIST.md`
  六阶段 22 个复选框全空，而 `step-check` 判第 1、2、4 步已完成——两套事实互相打脸，且没人能说清哪套算数。
- 每轮注入的 `.dsh-hooks/context.md` 只列 3 个工作区并写「另有 7 个进行中的工作区未列出」，
  执行者看不到全局，也不知道自己那一步离门禁还差什么。

需要的是一个**逐步骤、可 diff、只追加**的声称层，以及一条「声称与核对不一致就点名」的判定。

## 决策

1. **事实源顺序固定为三层**：产物 → `step-check` 的 verdict → 台账的 claim。
   台账只做对照，**永不参与 `advance`、永不改写门禁结论**（本轮如此，转硬门另立 ADR）。
2. **台账落 `models/_drafts/<模型-id>/workflow-ledger.json`，随工作区进 Git**。
   不进 `.model-lab/`（那是被忽略的本机状态，不可 diff、不可评审）。
3. **schema_version 1.0**：`workspace / workflow / steps[] / checkpoints[]`；
   steps 项含 `step / name / status / owner / started_at / updated_at / evidence[] / gate{}`；
   status 六态 `pending | in_progress | partial | done | blocked | skipped_external`。
4. **只追加**：`checkpoints[]` 只能向后追加；手改成截断即 `ledger_append_only`，
   每步的 status/owner/updated_at 必须与最后一条 checkpoint 一致，否则 `ledger_schema_invalid`。
5. **status 只是声称，verdict 由 `step-check` 现场重算**：`gate.claimed` 是登记值，`gate.verdict` 是核对值。
   `claim=done` 而 `verdict≠done`、`claim=partial` 而 `verdict∈{pending, missing}` 判**漂移**。
6. **写入门禁**：`done` / `skipped_external` 必须至少一条证据；同一步换 owner 拒绝（`ledger_owner_conflict`）；
   文件证据必须落在工作区内、存在、非链接，记相对路径 + sha256 + 字节数。
7. **本轮只做 advisory**：`step-check` 追加 `ledger:<步骤>` advisory 项，不改变 `ok`、不改变退出码；
   `ledger check` 自己退出码 0＝一致、1＝漂移，只作用于该子命令。
8. **不靠 hook 强制**：守卫的 `delegate` 只覆盖 `pwsh`/`write`/`edit`/`read` 四类工具，
   `run_code`、WSL、外部编辑器全绕过；装它只会制造「以为有闸门」的错觉（见 ADR 0048）。
9. **`.dsh-hooks/context.md` 从台账读**：有台账的工作区固定三行（状态 / 前沿缺项 / 下一步命令），
   无台账回退旧写法；预算 1400 字内按优先级尽量多列，省略行给出被省略数量与查看命令。

## 后果

- 10 个在役草稿工作区目前都没有 `workflow-ledger.json`，`ledger show` 显示「未建立」且不报错；
  逐步登记后才会出现漂移判据的实际价值——这是 advisory 先行的代价，也是先观察一轮的原因。
- `models/_drafts/` 不参与分发（分发只选 `models/sample-water-model/` 与文档），台账不会泄进公开仓。
- 转硬门前需要一批真实台账数据回答两个问题：漂移率、以及 `done` 的证据是否真的可核对；
  若漂移率长期为 0 而台账长期为空，说明登记成本高于收益，应当降级为可选而不是转硬。

## 被否决方案

- **复用 `workflow-state.json` 记步骤**：它是派生快照，每次 `advance` 整份重写，无法 append-only，也无法保留历史声称。
- **台账放 `.model-lab/`**：被 `.gitignore` 忽略，不可 diff、不在评审范围内，等于把事实又藏回本机。
- **hook `delegate` 校验写入**：四工具覆盖面之外全是洞，且插件不在本仓、不能随仓库版本化。
- **直接上硬门（`advance --require-evidence`）**：没有历史台账，一次性硬门会把 10 个在役工作区全部卡住。
