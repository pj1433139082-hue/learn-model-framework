以及解释器与虚拟环境和 `.pyd`/`.so` 不进入普通 Git 历史，全部继续有效。

## 决策

模型实验室的正式训练、验证、MLflow 打包和部署统一使用 Python 3.11。
仓库主工具的兼容范围固定为 `>=3.11,<3.12`，本地默认环境命名为
`.venv-311`。新模型继续默认使用 `linux-x86_64-py311-mlflow222` Profile；
CPU、GPU 和 Chronos 共用同一 Python minor 版本约束。

模型清单记录允许的 Python minor 范围，实际 MLflow 制品中的
`python_env.yaml` 与 `conda.yaml` 必须记录构建时的精确 Python 补丁版本。
训练、打包与部署环境必须彼此一致。若使用 PyArmor，原生 Runtime 还必须
同时匹配 `cp311`、目标操作系统和目标架构。

## 兼容边界

- `windows-x86_64-py312-legacy` 只用于解释和维护已有 Python 3.12 历史记录，
  不得用于新训练、新打包或新部署。
- 当前八个在役模型及其历史发布快照不重写。模型需要修复时保留原版本，使用
  Python 3.11 形成新的语义版本、验证证据和发布快照。
- `scripts/构建归档/`、历史部署教程和学习 Notebook 继续保留 3.12 内容作为
  审计证据；公共入口、活动分析脚本和可视化脚本统一使用 3.11。
- Python 解释器、虚拟环境、`.pyd` 和 `.so` 不进入普通 Git 历史。仓库保存
  环境契约、精确依赖锁和静态制品验收结果，而不是打包本地解释器。
- 真实远端发布后端仍然禁用；本决策不构成上传或平台写入授权。

## 后果

开发者只需要维护一个正式 Python minor 版本，避免 3.12 构建出的 MLflow
环境文件或 PyArmor Runtime 被送入只能运行 3.11 的平台。代价是旧 3.12 工具
不能直接参与新发布；如需修复旧模型，必须以新版本方式迁移并重新验证。
