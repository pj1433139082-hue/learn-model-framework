# ADR 0055：仓库检查器单一入口（注册表 + 薄壳脚本）

- 状态：已接受（2026-10-21）
- 相关：ADR 0046（分发仓库文档从本仓拷贝）、ADR 0048（守卫边界契约）、docs/10-流程层/26-现场数据接入流程.md

## 背景

仓库里有四个各写各的检查脚本，都是「解析 argv → 自己实现检查 → 自己打印 → 自己返回退出码」：

1. `scripts/check_layout.py`——工作区与 data 骨架，带 `--model`，无测试；
2. `scripts/check_docs_layout.py`——docs 分层骨架，无参数；
3. `scripts/check_release_docs.py`——发布后登记核对，带 `--json`；
4. `scripts/check_publish_readiness.py`——发布通道与部署件判定，带 `--model`（必填）与 `--json`。

四份脚本的物理形状几乎一样，却没有共同入口：判据不能按名字调用、结果不能按名字聚合，想在测试里跑一次「全部检查」只能起子进程解析文本。其中 `check_layout.py` 连单元测试都没有，改规则时只能靠肉眼看输出。新增第五个检查时，唯一可复制的模板就是再抄一份 150 行的 argv + print + 返回值。

这就是典型的浅扇出：四个入口共享同一段流水线形状，却各留一份实现；真正的判据（哪些目录必须存在、哪些登记必须齐全）埋在只能整体执行的脚本里，任何一处想复用都要复制粘贴。

## 决策

1. **判据收敛到一个注册表**：`model_lab/repo_checks.py` 提供 `CheckResult(name, ok, issues, warnings, summary, detail)` 与 `CheckSuite`，注册表 `CHECKS` 的键固定为 `layout`、`docs-layout`、`release-docs`、`publish-readiness`；`run_check(name, root, **options)` 跑单个、`run_checks(names, root)` 聚合并按「任一失败则整体 ok=False」给结论，未知名字抛 `ValueError` 并列出可用名字。
2. **脚本只做薄壳**：四个脚本保留原有参数名、stdout 文本与退出码，`main` 只剩「`argparse` → `run_check` → `render` 打印 → 退出码」四步；判据、报告与渲染都在注册表里，禁止两份实现。渲染器按检查名分派，逐字复刻改造前的输出（含空行与 `--json` 结构）。
3. **测试按注册表写**：`tests/test_repo_checks.py` 锁名单、未知名字、聚合语义与四个真实检查；`tests/test_check_layout.py` 用临时目录锁骨架判据；薄壳另有一条「`main([])` 的输出与注册表渲染逐字一致」的用例，防止脚本与注册表再次漂开。
4. **参数只走 options**：检查函数签名统一为 `(root, **options)`，`--model` 这类开关由脚本翻译成关键字参数（`model=`、`json_output=` 只在渲染层），注册表本身不读 argv。

## 后果

- 新增检查只需写一个 `_check_*` 函数、在 `CHECKS` 登记一条、补一个渲染分支；脚本层可以完全不新增文件（CI 需要独立命令时再加一个 20 行薄壳）。
- 判据第一次可以按名字调用与断言：四个检查在仓库根的结果、临时目录上的违规、聚合退出语义都在单元测试里，不再依赖子进程文本匹配。
- 改造前后七个场景（三个结构检查、发布登记 JSON、发布前置的三个工作区）的 stdout/stderr 与退出码逐字节一致（sha256 比对，基线详见验收记录），外部引用方（`.github/workflows/workflow-state.yml`、AGENTS.md 里的命令）无需改动。
- 代价：渲染仍是「每个检查一个函数」，新增检查若输出形态特殊，仍要写渲染分支——注册表统一了判据，不假装统一交互形态。
- 已知限制：脚本为了能直接 `python scripts/xxx.py` 运行，各自保留四行 `sys.path` 引导与兼容性别名（`LAYER_DIRS`、`Report`、`check_deploy_assets` 等），这些只是转发，不是第二份实现；把参数全塞进渲染层意味着 `--json` 的字段结构仍由各渲染器决定。

## 被否决的方案

- **维持四套实现**：现状，判据无法按名字复用，`check_layout.py` 至今没有测试；新增检查只能再复制一份 argv 模板。
- **全部塞进 `cli.py` 的命令表**：`model_lab` CLI 面向模型工作区生命周期，仓库自检是开发侧工具；塞进去会把「模型实验室」与「仓库治理」两个变更频率不同的面绑在一起，也让 CI 的 `python scripts/check_*.py` 引用全部失效。
- **引入插件框架/入口点发现**：四个检查就是四个函数，注册表字典已经够用；插件机制带来的安装期与发现期成本换不来任何判据复用。
- **只做一层共享 `main()`，判据仍留在脚本里**：能消掉重复的 print/退出码，但测试仍要导入脚本模块、仍拿不到可按名字调用的结果对象，聚合语义也无法实现。
