# ADR 0053：子智能体协作契约（写作用域、机器回执、证据 locator、cwd 纪律）

- 状态：已接受（2026-10-21）
- 相关：ADR 0048（守卫边界契约）、ADR 0052（步骤台账）、docs/agents/issue-tracker.md

## 背景

长任务已经常态化为「Lead 派具名子代理、子代理改一段、回报正文」。实测下来有三个失效点，都不是态度问题：

1. **写作用域只在自然语言里**。子代理越界写一份文档、顺手改一个测试，没有任何一步会报错；等到验收才发现两份改动缠在一起，分不清是谁的。
2. **子会话的 hook 设置按 cwd 解析**。`.dsh-hooks/` 的纪律只在仓库根生效，子代理换个 cwd 启动，守卫与注入块静默失效——不是被绕过，是根本没读到。
3. **交付不可审计**。「我改完了」是对话正文，没有机器可读的痕迹：改了哪些文件、跑的哪条命令、退出码多少、证据文件是哪份，事后只能靠翻聊天记录。

同时必须承认守卫的真实边界（ADR 0048）：它只覆盖 `pwsh`/`write`/`edit`/`read` 四类工具调用，`run_code` 与 WSL 可以绕过；因此这条契约选择**不新增机器强制**，而是把可核对的东西固定下来，由 Lead 复核。

## 决策

1. **写作用域先声明后开工**：每张卡在工作看板的 description 里写明「写域」——目录或文件 glob 清单（例：`models/_drafts/<id>/**`、`model_lab/ledger.py`）。子代理只在写域内写；需要跨域先回报 Lead，由 Lead 扩域或改派，不自行扩大。
2. **机器回执三件套**：交付必须同时给出
   - 改动清单：`git status --porcelain` 中属于自己写域的路径（逐行列出，含 `??` 未跟踪项）；
   - 复跑命令与退出码（例：`pytest tests/test_ledger.py -q` → `27 passed`，exit 0）；
   - 台账/看板上的 claim：`owner` 用子代理名，`evidence` 指向真实产物。
3. **证据 locator 统一写法**：文件类写成 `file:<相对仓库根的路径>#sha256=<前 12 位>`，命令类写成 `cmd:<命令> -> exit <n>`，回执类写成 `receipt:<工作区内相对路径>`。与 `model_lab/ledger.py` 的三类 evidence（`file`/`receipt` 必须落在工作区内且存在、`cmd` 记命令原文）同一套口径，不另造格式。
4. **cwd 纪律**：子代理一律以**仓库根**为 cwd 启动；产物路径按仓库根写，不写「我这边」这类相对口语。发现自己的 cwd 不是仓库根时停手回报，不带着失效的纪律继续写。

## 后果

- 写域冲突从「事后发现」变成「事前声明」，两份改动不再缠在一起。
- 交付从「正文承诺」变成可复核的三件套：清单、命令、claim；Lead 只需对照 `git status` 与 `step-check` 就能判真伪。
- 代价：每张卡多写一段写域；子代理报告变长；仍需人工复核——本契约不新增机器强制，违反者靠 Lead 与 `step-check` 发现。
- 已知限制：本契约对 `run_code`/`WSL`/外部编辑器没有拦截能力（同 ADR 0048）；看板卡是事实源与验收锚点，不是调度器，不能用它推断任务一定被跑过。

## 被否决的方案

- **用 hook PreToolUse 拦子代理写入**：只覆盖四类工具调用，且钩子不知道「这张卡声明的写域」是什么，只能退化成按路径白名单，误拦率高、拦不到的照样绕。
- **每个子代理一个独立 git worktree**：隔离最彻底，但 `_drafts` 里的跨工作区引用（模型产出、归档记录、发布回执）会在合并时反复打架，成本高于收益。
- **保持现状（只在对话里约定）**：即本 ADR 的背景三条，不可审计，已证明会漂。
