# ADR 0060：镜像计划单一内核

- 状态：已接受（2026-10-21）
- 相关：ADR 0046（分发文档单一来源）、`model_lab/mirror.py`、`model_lab/distribution.py`、`scripts/export-model-repo.py`

## 背景

仓库里有两条“把一组文件落到目标目录”的流水线：

- `model_lab/distribution.py`：按剥离清单挑选文件，生成 11 份文档，`--apply` 时写入分发仓；要求原子写、sha256 清单、dry-run 绝不写盘。
- `scripts/export-model-repo.py`：把单个模型工作区镜像到独立导出仓；要求保留导出仓根资产、删除源里已不存在的受跟踪文件、公开档先脱敏再落盘。

两条流水线各自实现了一遍“创建目录、临时文件 + 替换、复制、算摘要”。行为细节已经开始分叉：一处漏了路径遍历校验，另一处的原子写只在文本分支有。继续各写一份，下一次修 bug 还要记得改两处。

## 决策

1. **一个机械内核**：新建 `model_lab/mirror.py`，只提供 `MirrorFile`（相对路径 + 源文件或内存文本，二选一）、`MirrorPlan`（`add_text`/`add_file`/`add_tree`）、`MirrorResult`（`manifest`/`written`/`bytes`）与 `materialize(plan, target, *, transform=None)`。
2. **内核不懂业务**：不 import distribution 或导出脚本；分发哪些文件、生成哪些文档、公开档怎么脱敏，全部由调用方在构造计划时决定。
3. **落盘约束写在内核**：相对路径必须是 POSIX 相对路径，拒绝绝对路径、盘符与 `..`；落盘前再用 `resolve().is_relative_to(target)` 复核；文本原子写（`.name.tmp` + `os.replace`），源文件 `copy2`；每个落盘项算小写 sha256。
4. **transform 只作用于文本**：调用方传入 `transform(text, dest) -> str | None`，返回字符串表示改写、返回 None 表示原样；二进制源文件原样复制。公开导出的脱敏与 owner 替换走这一个入口。
5. **消费方各自保留业务尾部**：`distribution.publish_distribution` 只负责构造计划、生成物预检与报告语义；`export-model-repo.stage` 只负责计划、README/公开档附加与返回 manifest。导出仓的“删除源里已不存在的受跟踪文件”仍留在 `mirror_git`，因为它需要 git 状态，不属于文件镜像。
6. **dry-run 不调用 materialize**：预览只构造计划并统计，绝不触碰目标目录。

## 后果

- 原子写、路径遍历校验、sha256 清单只有一份实现，两条流水线不会再各自漏一项。
- 导出脚本接入内核后，公开档的改写与普通落盘走同一条路径，脱敏不再有“文本分支才生效”的旁路。
- 代价：`MirrorPlan` 要同时容纳文本与源文件，类型上比两个专用函数啰嗦；调用方仍要自己保证“计划里没有敏感文件”。
- 已知限制：内核不负责回滚，写到一半失败会留下已落盘的前缀；不负责删除目标里多余的文件（分发与导出的清理逻辑仍在各自模块）；不负责编码转换，文本一律 UTF-8。

## 被否决的方案

- **保留两套实现，只把公共函数抽成工具函数**：调用方仍要自己记得先校验路径、再原子写、再算摘要，漏一步就分叉，和现在一样。
- **用 rsync/robocopy 这类外部同步工具**：跨平台行为不一致，生成物与脱敏改写无法插进复制过程，dry-run 也拿不到 sha256 清单。
- **让 distribution 直接调用导出脚本**：导出脚本带 git 提交/推送与模型工作区语义，分发只需要文件落盘，依赖方向反了。
- **把删除多余文件也放进内核**：删除需要“哪些是受跟踪文件”的 git 知识，内核一旦知道 git 就不再是纯机械层。
