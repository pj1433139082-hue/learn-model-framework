# 0051 否决带向量检索的跨会话记忆：召回泄漏不可审计

> 本 ADR 保留私有源仓原文；`step-check`、`ledger`、`.dsh-hooks` 在本公开框架分发仓未实现，请以 `status`、`context`、`.codex/hooks.json` 为准。

- 状态：已接受
- 日期：2026-10-20

## 背景

本轮评估第三方智能体工程（上游源码核对，任务看板 T6）时，ruflo 的记忆机制被列为候选：把项目知识写成向量库，会话开始时按相似度 top-k 召回进上下文。它对"跑偏"看似有用——上下文里总带着历史结论。

但在模型实验室里，这条路径会破坏验证结论的可信度：

1. **验证留出（holdout）的派生文本没有路径标记**。留出集被读过一次、摘要过一次、特征里出现过一次，它的派生文本就和普通笔记无法区分；一旦进了向量库，后续任何一次 top-k 召回都可能把它拉回上下文。
2. **门禁看不到向量库内部**。`step-check`、`release-gate`、守卫（ADR 0048）能审计的是文件系统与命令行：文件在不在、命令跑没跑、摘要对不对。向量库是一次黑盒检索，没有可 diff 的产物，也没有可断言的隔离边界。
3. **泄漏的后果是静默的**。模型"见过"留出集之后，验证指标仍然会算出来、仍然漂亮，只是不再代表泛化。现有判据不会报警——这正是最难事后发现的一类错误。

换句话说：文件型记忆可以被审查，向量型记忆只能被相信。

## 决策

1. **不引入任何带向量检索的跨会话记忆**作为模型实验室工具链的一部分；包括"只装记忆、不装 hooks"的裁剪用法。
2. **记忆只能是文件型**：可 diff、可 review、可只读审计、可整份重写。项目现有的 `workflow-state.json`、`CONTEXT.md`、`models/_drafts/<模型-id>/` 下的台账都属于这一类（台账演进见 T1）。
3. **若将来要重新考虑**，必须同时满足三条，缺一不可：召回结果可导出成可读日志并进 Git；留出集在入库前被物理隔离（不进任何索引）；有机器断言能在召回日志里检出"留出派生文本"。三条都做不到就维持本决策。
4. **ruflo 只作参考，不接入流程**：可以参考它的 hooks 记账思路（Pre/PostToolUse 记账不阻断）与任务看板形态；其 memory 机制一律不采纳。

## 后果

- 项目知识库继续以 `CONTEXT.md` + `docs/` + 工作区台账为唯一载体；跨会话"记住"靠重新读取文件，不靠向量召回。
- 本地 `ruflo-main` 副本即使替换成最新上游源码，也只作为参考资料存在，不进入任何技能、hook 或技能同步链路。
- 这条否决是**结构性**的：它不取决于 ruflo 的实现质量，也不因为上游修复某个 bug 而失效。

## 被否决方案

- **装 ruflo 记忆当项目知识库**：召回质量与可审计性不可兼得；风险落在验证结论上，代价不对称。
- **只装 memory、不装 hooks**：hooks 是否安装与召回是否发生无关，泄漏路径不变。
- **top-k 召回后按路径过滤掉 holdout 目录**：留出集的派生文本通常不带原路径（摘要、统计量、特征名都是），过滤规则挡不住真正要挡的那部分。
- **用"提示模型别看不该看的东西"代替机制**：与 ADR 0048 同一条理由——提示不是门禁。
