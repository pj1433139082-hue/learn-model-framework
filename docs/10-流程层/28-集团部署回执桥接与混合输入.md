# 28 集团部署回执桥接与混合输入

> 公开边界：本页定义“设计/验证证据怎样与集团部署回执对接”，以及“IoT + 化验/人工值”怎样声明。公开仓不包含集团部署 kit，也不执行 group 上传。

## 1. 两条能力的边界

- `model-lab` 负责需求、设计、数据质量、实现、测试、验证和本地生命周期状态。
- 集团 `deploy.py` / `infra_model_deploy` 负责 Windows 本机的 Step 1/2/3、上传 Run 和平台参数配置。
- `releasable` 仍是公开框架中唯一要求固定实包的阶段；集团回执不等于公开 `mlflow-bundle-valid`。

## 2. 集团回执登记格式

拿到集团 Run 回执后，在模型工作区写 `validation/publications/<run_id>.json`。建议字段：

```json
{
  "schema_version": "1.1",
  "channel": "group",
  "model_id": "<model-id>",
  "model_version": "<version>",
  "experiment": "<平台实验名>",
  "run_id": "<MLflow Run ID>",
  "company_package_sha256": "<ZIP SHA-256>",
  "deploy_kit_sha256": "<kit SHA-256>",
  "status": "verified_group_receipt",
  "verified_at": "<带时区 ISO-8601>"
}
```

- 集团回执不写 `bundle_sha256`、`plan_id`，不声称 Linux 目标已验证。
- 公开仓没有 `group` 上传命令；此文件是登记格式，不是发布授权。
- 真实上传仍需要平台实验名、作者标识和用户明确指令。


### 2.1 登记命令

```powershell
& .\scripts\model-lab.ps1 publication import <工作区> `
  --run-id <32 位小写十六进制 Run ID> `
  --experiment <平台实验名> `
  --company-package <infra_model_deploy.zip> `
  --deploy-kit scripts\deploy-kit\<model-id> `
  --format json
```

命令只校验本地文件摘要并写 `validation/publications/<run-id>.json`；不访问平台、不上传、不执行 kit。
## 3. 混合来源输入

`model.yaml` 的 `contract.inputs` 仍然只声明物理输入。来源、供数方式和时间口径写在 `inputs.md`：

| 输入 | 类型/单位 | 来源 | 供数方式 | 时间口径 / 质量 |
| --- | --- | --- | --- | --- |
| `Q_in` | number, m3/h | IoT | 请求直接传 | 当前分钟，缺失则标记 `Valid=0` |
| `COD_in` | number, mg/L | 化验 | 请求直接传（最近一次） | 化验日 + 采样时间；超过 24h 标记 stale |
| `NH4_in` | number, mg/L | 人工 | 请求直接传 | 班次录入时间；超时标记 stale |
| `upstream_flow` | number, m3/h | 上游系统 | 请求直接传 | 上游时间戳，晚于请求时间则拒绝 |

规则：

1. 推理请求必须携带全部输入；模型不得在推理时现场取数。
2. 每个非 IoT 输入必须声明采样时间或业务时间，并定义 stale 上限。
3. 缺失/超时输入用显式 `Valid` 或质量输出表达，不能静默填 0。
4. `aux_dict` 只用于部署样本或离线校验，不替代在线请求字段。


核对命令：

```powershell
& .\scripts\model-lab.ps1 input-check <工作区> --format json
```

`mixed-inputs-declared` 会在 `status` 门禁中出现；非 IoT 输入缺 `供数方式` 或 `时间口径/质量` 时阻断。
## 4. 边界与仍未实现

- 公开仓没有 group 上传适配器；`publication import` 只登记，不访问平台。
- `inputs.md` 的来源/供数方式由 `input-check` 和 `mixed-inputs-declared` 校验；`model.yaml` 的 `contract.inputs` 仍只声明物理字段。
- 真正上传和平台绑定仍由集团 `deploy.py` 执行，需要实验名、作者标识和明确授权。
- 非 IoT 输入的 stale 上限目前是声明和门禁字段，真正的在线拒绝策略要在模型实现里体现。
