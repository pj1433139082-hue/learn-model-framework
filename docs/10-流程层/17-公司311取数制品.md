# 公司 Python 3.11 取数制品（#17）

Linux 测点模式需要在该模型的 `model.yaml` 中声明受控来源与组件 SHA-256；构建时用 `--iot-package-zip` 显式指定公司发放的 `infra_model_deploy.zip`。框架只读取 ZIP 内 `resources/infra/311` 的模块、PyArmor 初始化文件和 `linux_x86_64/pyarmor_runtime.so`，不会按包内 README 执行旧部署脚本，也不会复制 3.10/3.12、Windows `.pyd`、本机解释器、虚拟环境或凭据文件。ZIP 本身及密文组件不进入 Git。

本机的 `framework/` 是这份 ZIP 的解包副本，整目录同样不进入 Git；其中密文模块、原生 Runtime 与初始化器由 `scripts/验收/install_company_runtime311.py` 从钉住摘要的整包重建。它不能当构建来源：安装器把 PyArmor 初始化文件按 LF 落盘，得到 1955 字节 / `7fa85a63f805106aec215e8109110157bee71fc09c610d5786c01b6fe0441083`，而上面钉住的 `runtime_init_sha256` 是包内原始 CRLF 形态的 2008 字节 / `b84c5aee…`。两者行内容相同、字节摘要不同，`provider_archive` 按字节比对，因此只会接受 ZIP 那一份。`framework/` 里的 `test_env.py` 与 `deploy_template_iot2.py` 也不是包内原件：包内两份都指向 3.12 模块，本机这两份是改到 3.11 的副本，随目录一起留在本机、不再入库，安装器也不重建它们。

以下摘要对应本次收到的公司 ZIP；若公司换包，需重新核对并更新当前模型的声明，不能跳过校验：

```yaml
target:
  environment:
    operating_system: linux
    architecture: x86_64
    python: ">=3.11,<3.12"
    native_runtime:
      kind: pyarmor
      python_abi: cp311
      platform: linux_x86_64
      artifact: company_iot_native
serving:
  provider:
    kind: company-iot-311
    archive_sha256: 06f08382f652c303d451fb1770114a546babba5388247185729e46fd2e793942
    module_sha256: 86a2a28e9474684999e2d0f661284cb6e662c69e99b7c56a1cfc4e3c468c3332
    runtime_init_sha256: b84c5aee91521a6c83fdadd137c3c806b5064aa814c11c8e84f593c4d215d9d0
    native_sha256: 6567c0d8be7192482f5998b923dd7c10b81c66f02ca767761ae8ce6778519f79
artifacts:
  - name: company_iot_native
    kind: runtime
    uri: https://company.example.invalid/approved/pyarmor_runtime.so # 换成企业内无凭据的制品标识 URI
    sha256: 6567c0d8be7192482f5998b923dd7c10b81c66f02ca767761ae8ce6778519f79
```

这只是相关字段片段；其余 `model.yaml` 内容按该模型填写，不要照搬示例 URI。先在 Linux x86_64 的 Python 3.11 环境运行 `model-lab doctor`，再运行：

```text
model-lab bundle-build <model.yaml> --sample-csv <sample.csv> --iot-package-zip <infra_model_deploy.zip>
model-lab bundle-build <model.yaml> --sample-csv <sample.csv> --iot-package-zip <infra_model_deploy.zip> --apply
model-lab bundle-preflight <model.yaml>
```

构建器再次核对整包、三个组件和 ELF 架构；MLflow 包保留真实 3.11 模块、Linux `.so`、依赖锁、`python_env.yaml`、`conda.yaml` 及不含凭据的来源摘要记录。独立预检复核签名、映射和组件摘要。Windows 主机无法执行 Linux 构建，必须使用目标 Linux 3.11；离线测试可替换外部 IoT 请求接口，但该替身不打包。已有本地 Linux 3.11 实测：包在独立进程可加载、可离线推理，真实 PyArmor 模块可导入；#19 的近实时真实 IoT 取数与 MLflow 推理也已通过一次。这些通用冒烟结果不能替代各模型自己的窗口、测点和算法验收；历史长窗口模型仍需核对跨日与接口结束时间语义。测点信号和单位如有不确定性，应记录具体字段风险并补证据，不要求所有模型额外取得一份公司平台证明。证据与限制见 [真实 IoT 冒烟记录](./19-真实IoT冒烟阻塞记录.md)。
