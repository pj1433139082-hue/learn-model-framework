# 不引入外部自我改进框架

状态：已接受（2026-10-13）

## 背景

外部工作（RSI-Anything，Apache-2.0，Gen-Verse）把“提出候选 → 预测后果 → 选择行动 → 执行评价 → 反馈学习 → 保留改进”作为跨域闭环提出，并在代码修复、GUI 操作、实验室规划、反应优化等域给出了可复现结果。它真正可复用的部分是**编排语义**（薄适配器、由产物而非退出码定义成功、带身份的断点续跑），不是它的域实现：它的“世界模型”是每个域自训练的小网络，换域即需重训；而本体系的反馈源是小时到天级的现场工况数据，没有可用的自动评价器。它的 GUI 世界模型还使用研究许可证限制的第三方权重，不得进入公司链路。

本仓库的生命周期、门禁与证据链已经完整：改动可被验证、发布、归档与追溯。逐条对照之后，真正缺失的只有两条纪律——**同一改动的多候选与提前排序**（现状是先写一个实现再判它是否合格，落选思路与失败原因随讨论一起消失），以及**评价结论绑定判据**（现状是证据绑摘要，但没有“判据变了、旧结论作废”的通则）。因此本次决策是否定型：不全量接入，不 vendor 上游任何代码与权重，只把这两条纪律连同一条既有的诚实要求写进共同语言。

## 决策

1. **不引入外部框架、代码、依赖与权重**：不 vendor 上游仓库，不新增 Python 依赖，不引入其世界模型、预训练权重或研究许可证限制的模型；控制面与部署运行时的依赖面保持不变。上游作为方法来源在此致谢。

2. **不新建承载目录**：本仓库已有两个正式归宿——模型证据进 `models/<资产>/validation/`，当前一代工具脚本进 `scripts/<分类>/`，一次性运行器不落库。因此不新增实验目录：受追踪的 `experiments/` 等于在 `scripts/` 之外再造第二套工具目录与生命周期，非追踪的同名目录又与“证据入库”的既有文化冲突。本决策不产生任何新目录、新技能或新门禁。

3. **多候选与既有判据**：一次改动存在多种合理实现且难以回退时，先列出候选再动手；候选是否被接受，只能由该对象**已经存在**的可复现检查判定（单测、门禁命令、校验 CLI），不得为候选临时新造判据。

4. **事前判断只用于排序，不用于放行**：跑评价之前先写下取舍判断，事后与真实结果对照，判断失准如实记录。判断永远不是通过条件，不得代替评价，也不得据它跳过任何门禁。

5. **评价结论绑定运行身份**：一条评价结论的身份 = 被测对象摘要 + **评价器（测试与门禁文件）摘要**；任一项变化，旧结论作废必须重跑。环境（Python 次版本、依赖锁）不并入这层身份，仍由 `doctor` 与 `runtime-contract-valid` 单独表达，否则身份会脆到升级一次 Python 就全部失效。该身份的算法落为 `model_lab/verdict.py`：`evaluation_identity(workspace, *, object_paths, evaluator_paths)` 算身份摘要，`verdict_is_current(verdict, identity)` 判定一条已记录结论是否仍然有效。

6. **淘汰理由必须留痕**：写在改动自己的提交信息里；候选 ≥2 且结论会被反复引用时，同时挂到私有 Issue。不为此新增文档或索引。

7. **保留决定人工放行**：候选循环只输出胜出者、落选者与淘汰原因，采纳与否由人决定。它不得自动修改在役资产、不得自动提交、不得自动推送；远端写入仍按 [ADR 0004](./0004-发布必须显式授权且默认只读.md) 逐次授权。

8. **提供能力，不做强制**：这套纪律里可机械化的部分允许落成库函数（本次为 `model_lab/verdict.py`），但默认不强制——不接 CLI、不进门禁、不加校验脚本，也不要求任何既有流程调用它。最难自动化的恰恰是“事前判断是否诚实”，硬门禁只会催生填空式应付。

## 影响

- **适用面**：只用于“难以回退或有真实权衡”的改动，与 ADR 的既有触发面一致；模型侧改动天然落在这条线内（本来就难回退），两次改错别字不必写事前判断。
- **并发上限不变**：[ADR 0015](./0015-在役模型维护版必须安全分叉.md) 仍是并发候选的硬上限（同一父版本最多一份行为不变补丁草稿与一份契约升级草稿），本决策不放开它，也不改变维护草稿既有“（候选）”标注的含义。
- **不是证据**：候选、事前判断与淘汰理由都是工程决策留痕，不进 `validation/`、不参与发布门禁、不改变模型生命周期，也不能被包装成验收结论。
- **能力不等于流程**：`model_lab/verdict.py` 是控制面的普通模块（随 `model_lab*` 打包），既不进框架分发面（分发只含 `docs/` 与 `models/`），也不被任何门禁调用；调不调用它由使用者自己决定，不调用不算违规。
- **可再引用**：将来再讨论同类外部自我改进框架时，先引用本条说明当时为何不接入，避免重复论证；若届时要改变结论，须以新的 ADR 而非修改本条来推翻它。
