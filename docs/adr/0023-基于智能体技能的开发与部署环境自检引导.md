# 基于智能体技能的开发与部署环境自检引导

状态：已接受（2026-10-12）

## 背景

在模型实验室体系演进过程中，开发者与智能体经常面临异构环境的摩擦：
1. **控制面 Python 约束**：必须是 `>=3.11,<3.12`，系统偶发误选旧版 Python 3.12 或全局 Python；
2. **项目技能分发**：项目技能存储在 `.skillshare/skills/`，需通过 `skillshare sync` 同步至 `.agents/skills/` 供智能体感知；新克隆或新会话容易遗漏同步；
3. **目标部署构建异构性**：开发机为 Windows，而集团生产部署要求 Linux x86_64（需依赖 WSL 或目标容器）；
4. **私有部署能力包**：公司能力包（`infra_model_deploy.zip`）不入 Git，需要验证 SHA-256 摘要与安装状态。

借鉴 `setup-matt-pocock-skills` 的交互式探索模式（探索环境事实 -> 汇报就绪度 -> 逐项确认引导 -> 固化标准入口），我们需要为模型实验室量身定制原生自检引导技能。

## 决策

1. **确立 `model-lab-setup` 专属引导技能**：
   在 `.skillshare/skills/model-lab-setup/SKILL.md` 中维护该技能源码，作为环境与技能引导的唯一事实源，同步至 `.agents/skills/`。
2. **四维探测而不做隐式破坏操作**：
   自检技能按“探索事实而不假设”原则，只读探测四个维度：
   - 本地控制面 Python（3.11、虚拟环境、依赖健康度）；
   - 智能体项目技能（Skillshare 状态与同步完整性）；
   - 目标构建平台（WSL / Linux x86_64 及环境就绪度）；
   - 集团部署能力包（`infra_model_deploy.zip` 路径与哈希校验）。
3. **显式汇报与单步授权引导**：
   技能汇总探测矩阵，区分 `READY`、`MISSING` 与 `OPTIONAL`。缺少必要环境时，生成精确、确定性的修复命令，经用户确认后再执行，严禁静默下载未知依赖或破坏现有工作区。
4. **与既有入口分层协同**：
   `model-lab-setup` 专注环境就绪与脚手架对齐；就绪后平滑引导至 `model-lab-router` 进行业务模型需求与生命周期流转。
