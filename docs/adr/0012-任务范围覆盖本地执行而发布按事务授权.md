# 任务范围覆盖本地执行而发布按事务授权

状态：已接受（2026-09-24）

后续修订：下文“当前禁用的真实发布后端”仅是当时状态；现行固定实包
适配器及上传/业务运营边界见 [ADR 0016](./0016-固定实包发布替代全局禁用.md)、
[ADR 0017](./0017-发布验收与运营边界分离.md)。

## 决策

用户明确交办一个模型任务后，智能体可在该模型的本地工作范围内连续创建工作区、修改文件、运行测试、构建制品，并按 `model-lab` 门禁逐级推进到 `releasable`；不再对 `new --apply`、`bundle-build --apply` 或每次 `advance --apply` 单独追问授权。命令的显式 `--apply`、一次只推进一个状态、失败即停和 `decisions.yaml` 中未关闭的业务决定仍是硬门禁。模型、业务口径、文件范围或破坏性影响超出已交办任务时必须先停下核对。

同一时点可以独立回答的 `ASK` 与 `CONFIRM` 集中展示，一次回答后分别保存完整推荐和答案；可计算事实保存在证据中，不伪装成用户确认。此决定修订 ADR 0010 中“所有本地写入都要即时单次 `AUTHORIZE`”的交互要求，不改变其业务决定和机器门禁设计。

Git 远端变更和公司平台发布仍需明确的、限定目标与内容的任务指令。一次明确指令可以覆盖事先列明且内容未变化的连续远端步骤；推送不自动等于合并，上传不自动等于生产调度。发布界面对使用者只要求平台实验名（旧流程称模型编号）和发布作者标识（旧流程称账号）；目标适配器从已验证的 `model.yaml` 读取，制品摘要和环境兼容性由框架核验。作者标识不作为认证凭据。目标、制品或远端状态出现实质变化时，原指令不能继续使用。

本决策不启用当前禁用的真实发布后端，不允许运行历史上传脚本，也不废止 ADR 0002 的凭据边界。公司能力包只能作为兼容资料，不能因其自称免配置就视为已审查的发布实现。
