# 0046 分发仓库文档从本仓拷贝，正文只在 docs/ 存一份

- 状态：已接受
- 日期：2026-10-20

## 背景

公开分发仓（learn-model-framework）的几份治理文档此前**两处维护**：正文既在本仓 `docs/` 里，
又整段复制进 `model_lab/distribution.py` 的 `generate_distribution_artifacts()` 字面量，
生成分发产物时用的是后者。实测到的后果有三类：

1. **同一份正文会分叉**。`docs/agents/model-lab-skills.md` 本仓已经补齐了排障与维护段，
   字面量仍是旧副本，分发仓拿到的是过期内容。
2. **只活在字面量里的文档谁也读不到**。`docs/adr/README.md` 与五个层目录的 `README.md`
   只存在于字面量中，本仓没有同名文件：既不能被链接引用，也不能被测试与守卫按路径核对，
   改名后不会有任何东西报警。
3. **登记表随副本一起漂**。隐私剔除清单 `_DEFAULT_EXPLICIT_EXCLUSIONS` 里登记的
   `docs/10-流程层/18-多厂站与多测点开发规约.md` 从未在本仓存在（Git 全历史无此路径），
   说明"按路径登记"的清单只要没人核对存在性，登记本身就会退化成历史名单。

## 决策

1. **文档正文只在 `docs/` 存一份。** `distribution.py` 不再二次固化，改为按路径从本仓读取
   （`_REPO_DOC_ARTIFACTS` 十项 + `_read_repo_document()`）。文件缺失时生成前直接抛
   `FileNotFoundError` 并指出该读哪份 ADR，不静默退回旧副本。
2. **六个只服务于分发入口的 README 也在本仓落盘。** 单一来源的前提是"本仓按路径读得到"：
   `docs/adr/README.md` 与 `docs/{00-入口层,10-流程层,20-规则层,30-触发层,90-归档}/README.md`
   都写进本仓，再按路径分发给公开仓。它们的定位是"公开仓的目录入口说明"，本仓同名目录里
   多一份不冲突，改一次就两边同时成立。
3. **唯一允许的按目标仓渲染。** 本仓 `docs/agents/issue-tracker.md` 指向私有 Issue 跟踪器，
   分发版必须指向公开分发仓。这条差异由 `_DOC_RENDERINGS` 里的一条显式替换规则表达：
   锚点缺失即抛 `ValueError`。它存在的理由是公开仓不能泄露私有仓标识，不是允许按目标仓改写正文。
4. **一个例外：`models/README.md` 保留分发专用字面量。** 本仓同名文件是"工作区说明"
   （本仓模型目录怎么放、怎么用），直接拷给公开仓会泄露本仓工作区布局；分发版是另一种读者、
   另一种正文，因此它是第二份真实文档，不是副本。
5. **清单与文档同源核对。** 删除不存在的 `18-多厂站与多测点开发规约.md` 后，
   `tests/test_repository_layout.py` 增加断言：`_DEFAULT_EXPLICIT_EXCLUSIONS` 每条路径必须真实存在，
   且 `_REPO_DOC_ARTIFACTS` 每条源文档必须存在——登记一条读不到的路径等于永久漏剔除。

## 后果

- 改文档只改 `docs/`，分发产物自动跟随。核对方式是逐字节比对：11 份产物的 key 未变，
  其中 4 份与基线逐字节相同（`docs/agents/issue-tracker.md` 走渲染规则，
  `docs/agents/triage-labels.md`、`docs/agents/domain.md` 原样，
  `models/README.md` 是保留的字面量）；其余 7 份（`docs/adr/README.md`、
  `docs/{00-入口层,10-流程层,20-规则层,30-触发层,90-归档}/README.md`、
  `docs/agents/model-lab-skills.md`）与基线不同，因为本仓正文同时被扩写
  （层 README 补成"目录合同"、技能维护文档补齐排障与维护段）。这 7 份此后不存在
  "副本漂移"的可能：分发产物就是本仓文件本身。
- 分发产物此后不允许"故意与本仓不同"，需要第二种差异必须先有 ADR；`models/README.md`
  与 issue-tracker 的渲染规则是当前仅有的两处。
- 代价：`distribute` 预览与任何读产物的调用都要求本仓 `docs/` 完整存在；缺文件从
  "静默输出旧副本"变成"直接失败"，这是有意的取舍。
- 遗留：`docs/10-流程层/README.md` 仍以旧名解释公开仓为何缺
  `docs/10-流程层/18-多厂站与多测点开发规约.md`。该说法是历史解释而非可验证路径，
  若将来公开仓真的补入同名文件，需要同步正文（历史记录豁免，本次未改）。

## 被否决的方案

- **保留字面量，另加一条"与本仓同步"的检查**：检查只能报警，不能消除两份正文，
  分发产物仍可能在没人看的时候继续过期。
- **生成时直接拷贝本仓同名文件（含 `issue-tracker.md`）**：会把私有仓标识与私有入口
  写进公开分发仓。
- **只对本仓已存在的几篇去重，六个 README 继续留在字面量里**：单一来源只覆盖一半，
  "字面量里有、本仓读不到"的失配还会复发（`18-多厂站` 那条就是这样漏的）。
- **把分发产物改成模板渲染（变量化每一处差异）**：模板会把"文档"变成"带占位符的规格"，
  读者读到的正文与最终产物不再逐字节一致，且模板语法本身又要维护第二套。
