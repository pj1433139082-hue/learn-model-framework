# 模型交互决定进入生命周期门禁

状态：已接受（2026-09-23）；本地授权交互由 ADR 0012 修订

后续修订：本决策中的“远端发布后端禁用”仅记录当时状态；现行固定实包
发布边界见 [ADR 0016](./0016-固定实包发布替代全局禁用.md)。

## 决策

模型实验室采用“技能负责对话，`model-lab` 负责确定性门禁”的双层结构。
项目技能识别任务、调查事实、提出推荐并取得用户回答；命令层保持非交互，继续
通过 `new`、`status` 和 `advance` 提供可测试、可自动化的公共入口。

新模型模板版本 `new-model-v2` 生成 `decisions.yaml`。该登记册保存 `ASK` 与
`CONFIRM` 两类交互决定，并把每项决定绑定到其阻塞的生命周期转换：

- `ASK` 用于缺失信息；仅标为必填时阻塞转换；
- `CONFIRM` 用于会改变模型行为、验收口径或发布准备的选择，未确认时始终阻塞；
- `AUTO` 检查保存到原有证据和门禁结果，不写成交互决定；
- `AUTHORIZE` 不进入登记册形成长期许可；本地操作与远端事务的适用范围按 ADR 0012 执行。

用户回复“按推荐”时，登记册保存已经展示的完整推荐内容，不保存简写。确认记录
保留确认人和带时区时间；不强制区分业务、技术和发布角色。旧决定不得删除或静默
覆盖，改动时标为 `superseded` 并指向替代决定。

`model.yaml` 继续是身份、契约、版本和生命周期的唯一事实源；`model-spec.md` 与
验证报告保存业务理由和证据；`decisions.yaml` 只负责回答链和确认链。
`status` 报告当前待回答问题与待确认决定，`advance` 在当前转换仍有必填开放项时
拒绝推进。到达 releasable 后，状态报告生成决定登记册的确定性 SHA-256 摘要，供
未来真实发布快照绑定。

项目技能的 Git 事实源位于 `.skillshare/skills/`，通过 Skillshare 同步到仓库的
`.agents/skills/`，不使用 `superpowers`，也不依赖个人电脑上的 Ask Matt。入口路由
加五个场景技能分别处理需求设计、数据、构建验证、运行时发布和在役模型维护。

## 兼容边界

- 当前八个在役模型及其历史参数确认文档不批量改写；未来发生修复或新版本时才
  建立对应决定记录。
- CPU、GPU 和 Chronos 继续作为目标适配器，不拆分为三套生命周期技能。
- 真实远端发布后端继续禁用；本决策不构成任何平台写入授权。
- 没有安装项目技能时，`model-lab` 命令和静态门禁仍可独立运行。

## 后果

同事可以从一个自然语言入口开始协作，同时机器门禁能够判断哪些问题尚未回答，
避免“聊天里说过但项目没有记录”。代价是新模型在阶段推进前必须维护一份结构化
决定登记册，并在修改决定时保留替代链。
