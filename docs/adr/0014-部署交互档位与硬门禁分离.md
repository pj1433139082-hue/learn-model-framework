# 部署交互档位与硬门禁分离

状态：已接受（2026-09-26）

## 决策

一次模型任务可选择 `full-auto`（全自动）、`assisted`（半自动）或
`manual-review`（全手工确认）三个**交互档位**；默认 `assisted`。档位只决定
智能体何时汇报和等待，不改变 `model-lab` 的状态、`--apply`、Python 3.11、
行为基线、制品验证、业务决定和发布授权门禁。CPU、GPU、Chronos 及数值/测点
入参仍使用同一套生命周期，不按目标复制技能。

| 档位 | 本地可逆操作 | 业务决定 | 远端事务 |
|---|---|---|---|
| `full-auto` | 已交办范围内连续预览、应用、测试、构建和单步推进，失败即停 | 只使用已确认的答案；开放的必填 `ASK`/`CONFIRM` 必须停下集中询问，不得自答 | 仍须针对具体目标与内容的明确指令；已支持目标可走 ADR 0016 固定实包发布 |
| `assisted` | 自动完成可证明的事实调查和本地步骤，按阶段给简短结果 | 同一时点独立问题集中一轮，附推荐答案；答案记录后继续，不逐命令追问 | 单独一次限定事务确认；上传不包含生产调度 |
| `manual-review` | 只读调查自动进行；关键本地写入、构建和阶段推进先展示计划并等待确认 | 逐阶段确认，不把计算事实当作提问 | 每个目标与内容变化均重新确认 |

档位是**任务执行偏好**，不是 `model.yaml` 的模型身份/契约字段，也不是
`decisions.yaml` 中可复用的业务决定或永久发布许可。跨任务继续时先从任务记录
确认所选档位；没有记录就回到 `assisted`。用户可随时提高审查强度；降低强度
不能自动确认未回答的业务问题，也不能放宽发布授权。全手工档位不要求对只读
检查逐条批准。

新可写任务由路由技能在首次回复中展示三档并推荐 `assisted`，只选一次；
已有明确选择或续办同一任务不重问，纯只读诊断不弹选档。选档不另设本地
授权门禁；无答复时按 `assisted` 执行已交办任务，使用者可随时改档。各类任务的业务问答
由入口层的[任务问答与交互档位](../00-入口层/06-模型任务问答与交互档位.md)
分流，不用一份新模型问卷问完所有场景。同一轮已展示的独立决定可由一次
“全部按推荐”回答；未展示、尚依赖未来证据的决定不能预先视作确认。

八个在役模型的 Python 3.11 行为不变迁移默认按 `assisted` 执行：先保留旧发布
资产，再用新维护版本和固定输入行为基线证明兼容。旧版无基线、契约冲突或控制
动作不明时，只自动补证据；涉及业务口径的决定停止并集中请负责人确认。

## 安全边界

`AUTO`、`ASK`、`CONFIRM` 和 `AUTHORIZE` 仍表示问题或动作的性质，不与
三个交互档位同义。任何档位都不得调用历史 `deploy_*.py` 绕过禁用的发布后端，
不得把本地 `releasable` 说成公司平台已发布，不得把一次上传指令解释为允许
合并 Git 分支或启用生产调度。此决策延续 ADR 0004、0010、0012。
但真实 Run、回下载摘要与平台路径预测已验证后，也不得因本地仍是
`releasable`、未调用业务平台人工任务或按计划不调度而否认 MLflow 发布成功；
详见 [ADR 0017](./0017-发布验收与运营边界分离.md)。
