# 0040 工作区先于讨论，仓库根不是产物的家

> 本 ADR 保留私有源仓原文；`step-check`、`ledger`、`.dsh-hooks` 在本公开框架分发仓未实现，请以 `status`、`context`、`.codex/hooks.json` 为准。

- 状态：已接受
- 日期：2026-10-17

## 背景

一次真实的模型部署讨论（某厂风机效率核算）在**没有工作区**的状态下开始：会话直接从入口层文档进入，
讨论了几十轮公式口径，产出落在仓库根（`风机效率核算工具-公式口径问题汇总.md`、`风机效率核算公式-参数厂家核对清单.md`），
共用一份示例数据的 Excel 被当成真实口径反复计算，直到用户自己发现"那个 excel 里的数据都是示例"。
同一次讨论还在仓库根造出了被归档的旧一代目录 `学习/`，直接把一条既有测试
（`test_worktree_keeps_only_the_current_generation`）判红。

事后复盘：病根不是"文件放错目录"，而是**讨论发生在没有工作区的状态**——
沟通结论、参数表、核对清单、未决问题都没有固定归宿，只能落到最方便的地方；
而 SOP 里承载这些内容的 `decisions.yaml` / `model-spec.md` 在讨论开始时并不存在。

## 决策

1. **工作区先于讨论**：任何涉及模型设计、口径、参数的讨论开始前，必须先有 `models/_drafts/<模型-id>/`
   （`model-lab new --apply`）。**没有工作区时只做只读调研，不写任何产物**——调研结论留在对话里，
   等建好工作区再落盘。
2. **开工三件套**（工作区建好后立刻具备）：
   - `decisions.yaml`：本阶段必答的 ASK 清单（已有）；
   - **`inputs.md`**：每条被取用的输入一行，标明来源＝`真实` / `示例` / `待确认`；
   - **`questions.md`**：还没答案的问题一行，并写清"影响哪一步/哪个参数"。
   三者进模板（`model_lab/templates/new-model/base/`），由脚手架实例化，不手工复制。
3. **来源标记是硬要求**：用 `示例` 数据算出来的任何结论只能写成"机制验证"，不得当成模型口径；
   `step-check` 的①会核对 `inputs.md` 是否逐条标了来源、`questions.md` 是否还是空模板。
4. **仓库根纪律**：仓库根只放 `RESIDENT_ROOT_FILES` 列出的文件（2026-10-20 起 8 项，含
   `.gitignore` / `.gitattributes` / `pyproject.toml` / `.python-version`，见 ADR 0047），
   并且已归档的旧一代路径（`学习/`、`scripts/构建归档`、三份旧文档）不得出现在工作树。
   `step-check` 会点名越界产物；CI 里的 `step-check --repo-wide` 只判**被 Git 跟踪**的路径
   （干净检出看不到本地未跟踪数据），所以它不会把草稿的中间态误判成缺陷。
5. **hook 不是门禁**：hooks-kit 每轮注入"这一步还缺什么"+ 拦"往仓库根写模型产物"；
   剩下的判给人和 `advance` 的门禁，不新增第二套硬拦。

## 后果

- 讨论从一开始就有归宿，示例数据不会被当成口径（`inputs.md` 的来源列把这件事变成一条可核对的事实）；
- 仓库根的越界产物会同时出现在每轮提示和 CI 里，不再靠人事后回忆；
- 代价：开工多一步（`model-lab new --apply` + 填三件套），以及"没有工作区时不能写盘"会让
  纯探讨型任务无法沉淀文件——这是刻意的，探讨的价值在结论而不在文件。

## 被否决的方案

- **允许在 `docs/10-流程层/` 下写讨论稿**：看起来更省事，但正是它让"讨论产物"有了第二个家，
  而两个家等于没有家；真要有跨模型的流程性结论，走 `docs/10-流程层/` 的**正式文档**，
  不叫"某某讨论稿"。
- **让 hook 直接拦住未完成步骤的写入**：核对的结论需要人判断（历史缺口、跨模型讨论），硬拦会把正常讨论卡死。
- **把 `inputs.md` 的来源标记做成自由文本**：三个固定值才能被机器核对；自由文本会退化成"写了点东西"。
- **CI 里对草稿做九步齐备性判定**：草稿天生不齐，CI 会长期红着并被绕过；CI 只判客观的仓库根纪律。
