# 归档状态的单一推导

状态：已接受（2026-10-14）

## 背景与决定

“这个资产是否已完成归档”此前在五处各自推导，规则不同、松紧不同：

1. `model_lab/manifest.py` 的平台身份与制品 URI 一致性规则，按 `pending-archive` 标记逐项校验。
2. `model_lab/manifest.py` 的 `_pending_archive_paths`，另写一遍同样的判定，只为给出待归档路径。
3. `model_lab/asset_validation.py` 的快照与清单一致性检查。
4. `model_lab/catalog.py` 的档位渲染：只看 `platform.deployment_status` 与 `artifact.archive_status` 两个字段子集。
5. `model_lab/lifecycle.py` 的门禁用 `"pending-archive" in uri` 判断，**比清单松**：`artifact://mlflow/<experiment>/<run>/pending-archive.pkl` 这类合法文件名会被误判成“仍在待归档”，而 `platform.run_id` 为标记、制品 URI 已解析的清单又会被它漏判。

同形状的还有一处：快照的**写法与检法各写一遍**——`archival._render_snapshot` 与 `asset_validation._snapshot_issues` 各自定义同一份十键结构，两处漂移只能在写入之后以 `release_snapshot_mismatch` 暴露。

决定：**归档状态只推导一次，门禁与渲染只消费结论；快照结构写与检共用一份定义**。

1. **单一推导**：`model_lab/manifest.py` 暴露 `archive_state(document) -> ArchiveState`，把“是否待归档”的全部规则收在一个函数里：平台 `run_id` 或 `deployment_status` 为 `pending-archive`，或任一制品的 `archive_status` 为 `pending-archive`，或任一制品 URI 带 `artifact://pending-archive/` 前缀。返回值同时给出待归档路径与逐制品下标，供提示信息与门禁消费。
2. **单一快照结构**：`model_lab/manifest.py` 暴露 `snapshot_payload(document, *, captured_on, baseline_details=None)`，归档入口写快照与资产校验重算期望结构都调用它。
3. **门禁只消费结论**：`lifecycle` 的制品归档门禁改为读取 `archive_state(document)`，不再做 URI 子串匹配；目录生成器的档位同样改为消费 `archive_state`。
4. **路径清单保持适配器**：`_pending_archive_paths` 退化为 `archive_state(document).paths`，提示信息里出现的字段路径逐字不变。

## 边界

- **只允许变严**：本次唯一的行为变化是移除 `lifecycle` 的 URI 子串误判——它让拒绝集合变大（合法文件名不再被误判为待归档），而此前被拒绝的资产仍然被拒绝；清单校验器与目录生成器的结论对九份在役资产逐条不变。
- **规则本身不改**：`manifest.py` 的平台与制品校验规则逐字保留，本次只是让它们被调用而不是被各处重写。
- **不新增入口**：不新增 CLI 命令、不新增门禁、不新增远端读取；推导仍是纯本地、纯文件。
- **身份取值不在范围内**：`catalog` 里两处 `run_id != "pending-archive"`（`:235`、`:320`）是身份取值（渲染 Run 标识），不是归档状态推导，本次不动。
- 允许动的文件见卡片 #42；打包运行时与已归档发布包不在范围内。

## 后果

- 九份在役资产的档位重算不变：`02_前馈气量模型`、`03_曝气程序选择模型`、`07_雨季除磷加药优化模型` 为待归档，其余六份为已解析——与各自清单里的标记一致。
- 门禁不再可能被合法文件名误导，也不再可能漏掉 `platform.run_id` 上的标记。
- 快照结构的漂移从“写入之后才被发现”变成“写与检共用同一份定义”，同一处修改同时影响写与检。
