# 24 无 VPN 取数与公网路径验证手册（公开版）

## 1. 结论

**取数本身不要求 VPN。** 现场机器可能走公司内网，也可能走公网出口；先用 `scripts/取数探针/iot_path_probe.py` 判定当前路径，再决定取数方式。发布与平台在线验收是另一条链路，按对应发布文档执行。

## 2. 先探测

```powershell
python .\scripts\取数探针\iot_path_probe.py
python .\scripts\取数探针\iot_path_probe.py --json iot_path_probe.json
```

探测内容：

- 解析公司 IoT 端点地址，区分内网地址与公网地址；
- 读取路由表，报告出口网卡、最长前缀和是否 VPN/Tunnel；
- 对数据端点做一次无凭据 TLS/HTTP 探测，确认请求到达应用而不是只到防火墙；
- 输出建议路径和出口源地址。

它不读 token、不带 client secret，可以安全运行。

## 3. 判定

| 探测结果 | 取数路径 |
| --- | --- |
| 数据端点解析到内网地址，路由走内网网卡 | 内网直连 |
| 数据端点解析到公网地址，路由走公网网卡 | 公网直连 |
| 只有设置系统代理才通 | 显式设置 `HTTP_PROXY/HTTPS_PROXY` 后重试；不要默默依赖全局代理 |
| DNS/TCP/TLS 失败 | 先修网络或 DNS，不要用模拟数据绕过 |

## 4. 与发布的关系

- 取数：按本手册判定，不要求 VPN。
- 发布、在线验收、平台侧绑定：按发布通道要求走内网；不要因为取数能走公网就假设发布也能走公网。
- 代理地址、公司端点和凭据只从本机环境读取，不写进仓库文档或脚本。
