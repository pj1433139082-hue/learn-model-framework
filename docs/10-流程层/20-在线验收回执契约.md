# 模型专属在线验收回执

共享框架不包含旧模型的公式、真实测点或真实 IoT 测试。每个点位模型在私有目录执行自己的 `tests/test_real_bundle.py`，用真实接口查询并用独立口径计算预期；该测试负责证明数据来源与窗口完整性，不能仅把 `online_iot_fake` 置为 `false`。

测试通过后生成 `validation/online-acceptance.json`，`schema_version` 为 `1.0`、`profile` 为 `model-iot-v1`。回执包含 `model_id`、`version`、`provider_archive_sha256`、`bundle_sha256`、`binding_sha256`、`test_sha256`、`factory_code`、每个输入字段的 `point_codes` 数组、真实平台 `request_row`、`prediction_outputs`、独立 `oracle_outputs`、`raw_rows`、`window_rows`、`requested_at_utc`、`received_at_utc` 及 `online_iot_fake: false`。输出字典字段须与 `model.yaml` 的输出一致。所有真实编码和读数只保存在私有模型目录。

框架核对身份、文件摘要、请求数组、输出数值及时间顺序，再用 `request_row` 回载已上传的同一 MLflow 服务。它不能仅凭 JSON 字段验证公司 IoT 数据真实性；若测试未实际执行或证据不完整，不能宣称在线验收完成。旧模型特定回执格式应在私有侧迁移为该通用格式，或通过经审查的私有扩展实现，不将旧算法带进共享框架。

`model-iot-v1` 已在共享框架落地（`model_lab/online_acceptance.py` 的 `_verify_model_iot_receipt`），校验器自行重算而不是只信回执，因此回执还必须给出：`window_start_utc`、`window_end_utc`、`first_data_time_utc`、`latest_data_time_utc`、`window_timestamps` 与 `selected_readings`。窗口不采信回执日期，而由 `serving.start_field` 与 `serving.time`/`rolling_window` 反算（`target-date-day` 必须恰好是整日，`window_start_utc`/`window_end_utc` 必须与按 `iot_timestamp_timezone` 换算的结果一致）；`requested_at_utc` 不得早于窗口关闭时刻，`received_at_utc >= requested_at_utc >= window_end_utc`；`window_timestamps` 必须 ≥ `ceil(窗口 ÷ interval × 0.95)` 且 `window_timestamps <= window_rows <= raw_rows`；首末读数须落在窗口内并各自覆盖两端 `2 × interval` 的边沿。`selected_readings` 逐字段给出 `point_values`（每个声明点位在窗口内的最后读数，无数据写 `null`）与 `aggregated`，校验器按绑定的 `single`/`mean`/`sum` 以 1e-9 容差重算；`prediction_outputs` 与 `oracle_outputs` 的键必须与 `model.yaml` 输出逐字同名且逐项一致（容差 1e-6）。
