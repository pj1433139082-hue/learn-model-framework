# 27 模型发布路径选择与集团部署技能包（公开边界）

> 公开框架只包含框架自身的发布检查与固定 bundle 流程。集团部署技能包、`model-lab deploy-kit` 和集团 `deploy.py` 属于私有/集团通道，不随公开仓分发。

## 1. 先判通道

| 场景 | 通道 | 公开仓是否覆盖 |
| --- | --- | --- |
| 框架固定 bundle、Linux 目标、需要框架回执 | `model-lab publish` / 固定 bundle | 是（目标运行时按 Linux 3.11 要求） |
| 集团 `deploy.py`、读数式/point-code、Windows 本机 | 集团部署通道 | 否；使用集团技能包 |
| 没有部署 kit 的 point-code 模型 | 先安装集团 kit，再走集团通道 | 否 |

## 2. 集团部署 kit 的原则

- 集团 ZIP 由集团提供并审核；不要手工解压到不同目录；
- 安装器只提取 `infra_model_deploy/resources/infra/` 下的运行时和 `mlops_deploy_iot2.py`、`deploy_template_iot2.py`；
- 安装后核对 `infra.lock.json`：源 ZIP SHA-256、每个文件 SHA-256、安装时间、安装器版本；
- 不执行 `deploy.py` 或 `mlops_deploy_iot2.py`，不读凭据，不联网下载；
- 真实发布仍是外部动作，需要明确授权。

私有仓的 `model-lab deploy-kit install` 是该原则的实现；公开仓不提供同名命令。

## 3. 不要做的事

- 不要因为公开仓没有 `deploy-kit` 命令就手工复制运行时到 `scripts/deploy-kit/<model-id>/infra/`；
- 不要把集团 ZIP、凭据或 `infra/` 提交到 Git；
- 不要把 Windows 本机取数诊断当成 Linux 目标验收。
