# 26 现场数据接入流程（台账 → 点表 → 取数 → 数据质量 → 分析报告）

> 本文是 [11-新模型开发SOP](./11-新模型开发SOP.md) 中「③ 数据拉取与参数可视化」「④ 数据质量分析」的公开版展开。
> 公开仓只保留通用方法与可移植脚本；厂站台账、真实凭据和内部联调记录不随公开仓分发。

## 0. 一句话

从一份甲方台账出发，到「能支撑建模决策的数据质量结论 + 对外对接清单」为止：

**台账 → 点表 → 拉数 → 清洗 → 出图 → 报告 → 对外清单**。

每一步都落文件，不手抄、不口头传。

## 1. 产物落点

| 产物 | 落点 | 进 Git？ |
| --- | --- | --- |
| 台账原件 | 仓库外或 `data/台账/`（由项目决定） | 否 |
| 节点清单 JSON | `data/<模型-id>/nodes.json` 或工作区 `work/analysis/` | 可 |
| 原始 parquet | `data/<模型-id>/raw/` | 否 |
| 中间聚合 | `data/<模型-id>/derived/` | 否 |
| 分析脚本 | 工作区 `work/analysis/` | 是 |
| 数据质量结论、分析报告 | 工作区 `docs/` | 是 |
| 对外交付物 | `data/<模型-id>/delivery/` | md 可，office 否 |

约束：模型工作区内不得出现 `.parquet/.csv/.xlsx/.tsv`；原始数据只放仓库级 `data/<模型-id>/`。仓库根只放常驻文件，其余进 `models/_drafts/<模型-id>/`。

## 2. 工具与安装

公开仓提供可移植取数包：

```text
scripts/取数探针/
  iot-fetch-kit/          # 直连 REST 的批量取数包
  iot_bulk_fetch.py       # 仓库内薄入口
  iot_path_probe.py       # 网络路径探测，不带凭据
  iot_fetch_probe.py      # 真实 311 取数探针（需公司 provider）
  iot_ledger_to_nodes.py  # 台账 → 点表
  plot_signals.py         # 每个取用参数出图
```

安装取数包（任选其一）：

```powershell
# 方式 A：装进当前环境
& .\.venv-311\Scripts\python.exe -m pip install -e .\scripts\取数探针\iot-fetch-kit

# 方式 B：只设置 PYTHONPATH
$env:PYTHONPATH = (Resolve-Path .\scripts\取数探针\iot-fetch-kit).Path
```

## 3. 凭据

凭据只从环境变量或本地忽略文件读取，**绝不提交**：

```powershell
$env:IOT_CLIENT_ID = '<client id>'
$env:IOT_CLIENT_SECRET = '<client secret>'
$env:IOT_TENANT = '<tenant>'
$env:IOT_TOKEN_URL = '<token endpoint>'
$env:IOT_API_URL = '<data endpoint>'
```

也可以把凭据放到 `scripts/取数探针/iot-credentials.local.json`；该文件已在公开仓 `.gitignore` 中忽略。`iot_path_probe.py` 不需要凭据。

## 4. 台账 → 点表

```powershell
& .\.venv-311\Scripts\python.exe .\scripts\取数探针\iot_ledger_to_nodes.py `
  --ledger <台账.xlsx> --match <设备族> --signals V_IF,V_OP,V_P,V_ITIT `
  --out data\<模型-id>\nodes.json --md data\<模型-id>\点表.md
```

先 `--list-devices` 看台账里有哪些设备族。点位 ID 必须是「数采点位编号-数采信号名称」的完整拼接；少写尾缀时接口可能静默返回 null。

## 5. 网络路径先判定

```powershell
& .\.venv-311\Scripts\python.exe .\scripts\取数探针\iot_path_probe.py --json iot_path_probe.json
```

它只做 DNS/TCP/TLS 探测，不读凭据。取数可以走公网或内网；发布和在线验收的平台侧动作仍按项目要求走内网。详见 [24-无VPN取数与公网路径验证手册](./24-无VPN取数与公网路径验证手册.md)。

## 6. 批量取数

```powershell
& .\.venv-311\Scripts\python.exe .\scripts\取数探针\iot_bulk_fetch.py `
  --factory-code <FACTORY_CODE> `
  --nodes-file data\<模型-id>\nodes.json `
  --start "2026-01-01 00:00:00" --end "2026-01-08 00:00:00" `
  --out data\<模型-id>\raw
```

需要精确长区间、按月落 parquet 时直接用 `iot-fetch-kit`：

```powershell
& .\.venv-311\Scripts\python.exe -m iot_fetch --help
```

## 7. 出图与质量分析

```powershell
& .\.venv-311\Scripts\python.exe .\scripts\取数探针\plot_signals.py `
  --data data\<模型-id>\raw --signals V_IF,V_OP,V_P,V_ITIT --out models\_drafts\<模型-id>\plots
```

每个取用参数至少一张时序图。数据质量结论按 [11-新模型开发SOP](./11-新模型开发SOP.md) 的 ④ 交付：缺失、异常、分段、聚合口径、停机判据都要有实测量化，不写“看起来正常”。

## 8. 报告与对外清单

内部报告写工作区 `docs/历史数据分析报告.md`；对外交付物放 `data/<模型-id>/delivery/`。对外清单只写对接方需要的字段、单位、时间口径和缺失处理，不贴内部台账、凭据或原始数据。

## 9. 禁止事项

- 不把 `iot-credentials.local.json`、真实台账、原始 parquet 提交到 Git；
- 不用模拟数据宣称数据审查通过；
- 不把历史脚本里的 `fetch_iot_chunked` 当统一 API；
- 不在模型工作区根目录散落 parquet/csv/xlsx/tsv。
