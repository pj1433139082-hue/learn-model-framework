# v0.1.0 兼容与迁移说明

> 本页记录第一阶段状态；其中“发布后端仍禁用”已由
> [ADR 0016](../adr/0016-固定实包发布替代全局禁用.md) 修订。当前操作以入口层
> 00、03 和模型的实际 `publish` 回执为准。

`v0.1.0` 是模型实验室治理框架的第一阶段可用版本。它固定资产描述、离线
验证和发布前门禁，不替代现有模型实现，也不执行集团平台写入。

## 兼容边界

- Python：正式训练、验证、打包和部署统一为 `>=3.11,<3.12`；Python 3.12
  仅作为现有模型的历史兼容记录，不得生成新部署包。
- 清单：`schema_version: "1.0"`，工具兼容范围为
  `model_lab >=0.1.0,<1.0.0`。
- 目标：`cpu-iot`、`gpu`、`chronos` 共用一个验证与计划接口；GPU/Chronos
  仅验证元数据，不导入 PyTorch、Transformers 或真实权重。
- 资产：模型权重和原始大数据不进入普通 Git 历史；清单只保存稳定 URI、
  SHA-256 摘要和 `resolved` / `pending-archive` 状态。
- 行为：迁移不得隐含改变模型行为。旧脚本、Notebook、当前发布快照和历史
  快照继续保留；修复必须创建新的语义化版本，不得覆盖旧版本。
- 发布：发布后端仍禁用。`publish` 即使获得完整显式授权，也只返回
  `publish_backend_disabled`，不会读取长期凭据、初始化远端客户端或写平台。
- 退出码：`0` 为通过；`2` 为清单读取错误；`3` 为契约/目录错误；`4` 为
  发布被拒绝或阻断；`5` 为仓库发布门禁失败。

## 第一阶段发布门禁

在仓库根目录执行：

```powershell
.\.venv-311\Scripts\python.exe -m model_lab release-gate . --format json
```

该命令完全离线，覆盖 8 份在役清单、9 个当前/历史快照、中央目录、水力
延时行为基线、Chronos 夹具、发布拒绝以及完整普通 Git 历史。失败项同时
给出规则名和模型或路径，便于直接定位修复。

历史扫描默认拒绝凭据文件、可恢复密钥、压缩归档、模型权重、本地虚拟环境
和原始表格数据，并禁用浅克隆、懒获取与 replace 对象视图。唯一的表格例外
是 `tests/fixtures/` 下不超过 1 MB 的脱敏夹具；它必须在已提交的
`tests/fixtures/fixture-digests.json` 中登记 SHA-256，且所有可达历史版本都
必须保持同一摘要。未登记、超限、摘要漂移或清单孤儿均会使门禁失败。

## 下一批迁移

以下是 v0.1.0 当时的计划，不是当前固定实包上传的审批清单；
现行能力与边界以 ADR 0016/0017 为准。

1. 为前馈需气量、曝气模式切换和雨季判定补齐待归档的真实平台 Run 与制品
   URI；保留现有 `pending-archive` 记录作为审计证据。
2. 按风险和使用频率为其余 7 个在役模型逐一建立脱敏、确定性的行为基线。
3. 把离线发布门禁接入受保护分支 CI，并对规则版本进行固定和升级评审。
4. 设计真实平台适配器、短期凭据来源、审批证据、回滚与发布后核验；完成
   独立安全评审前不得启用远端写入。
5. 为外部制品存储增加摘要证明、保留策略和可恢复性演练，不把权重回填 Git。
