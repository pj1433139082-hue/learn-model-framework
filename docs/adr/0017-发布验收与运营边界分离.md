# 发布验收与运营边界分离

状态：已接受（2026-09-28）

## 决策

固定实包 `publish --apply` 的成功口径是：受支持的模型与目标环境通过预检，
用户已明确指定本次模型版本、实验和作者，远端 Run 为 `FINISHED`，上传的
`service` 回下载摘要与已验收实包相同，并通过平台路径加载与预测。满足这些
条件即可报告“MLflow 固定实包发布成功”；不得再以公司业务平台的人工任务
调用、生产调度、Git 推送或本地 `released` 状态作为这次上传的附加门禁。

公司业务平台的数采绑定和人工任务调用属于另一个集成验收范围。只有用户要求
验证该链路时才执行并报告其结果；未执行时如实写“业务平台调用未验证”，
不能倒推 MLflow 发布失败，也不能把它伪装成公司审批。一次性手动演示的
“不启用周期调度”是已确定的运营方案，不是待补缺项；启用生产调度、控制动作
或长期告警须有独立任务指令和相应模型专属验证。
新模型若已在需求决定中确认“一次性、不调度”，发布准备只需记录该结论，
不再增加一条重复的 `operations-plan` 确认；定时运营的决定在对应任务中处理。

`model-lab status` 只报告本地生命周期，不查询远端。`publish` 当前不会自动
把草稿从 `releasable` 提升为 `released`；正式归档仍须依据真实 Run、远端摘要、
预测回执建立可追溯发布快照，并由独立公共入口编排。这个本地归档缺口不得
表述成“尚未上传”或要求用户重复批准同一上传，也不依赖业务平台任务或调度。

测点身份、信号和单位要有与具体模型风险相称的证据；绑定记录、历史映射和
真实取数各自的证明范围须说清。框架不设“必须取得公司平台独立元数据证明”
这一通用外部手续。证据确实不足时报告具体模型和字段的风险，不把它变成
所有模型的额外发布审批。

本决策补充 [ADR 0016](./0016-固定实包发布替代全局禁用.md)；早期文档中
“发布后端仍禁用”“须独立安全评审后才可上传”仅是当时状态，不再适用于
已实现的固定实包适配器。
