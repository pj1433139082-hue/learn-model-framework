# ADR 0061：命令注册表与领域错误映射

- 状态：已接受（2026-10-21）
- 相关：ADR 0055（仓库检查器单一入口）、`model_lab/cli.py`、`tests/test_cli_command_specs.py`

## 背景

`model_lab/cli.py` 有 28 条命令，每条一个 `_configure_*` 与一个 `_run_*`。这看起来像“浅扇出”，但其中多数命令的参数面本来就不同：把 28 条强行塞进一张数据表，只会把差异藏进条件分支。

真正重复的是三处：

1. **领域错误映射**：`_workspace_error_result`、`_gpu_error_result`、`_manifest_error_result` 与 `record-online-acceptance` 里的内联分支，都是“exit 2 + 原 code + 原文案”，四份实现。
2. **三组工作区命令的尾部**：`advance`/`maintain`/`draft-fork` 都是“调用一个返回报告的动作、捕获 `WorkspaceError`、成功走 `_workspace_report`”，只有退出码不同。
3. **三组工作区命令的参数骨架**：都是“工作区 + 可选 version + 可选 change-kind + --apply + --format”，参数名、顺序、help 文案逐字相同。

## 决策

1. **`CommandSpec` 注册表是接口，28 个 `_configure_*` 是实现**：命令顺序、help、参数面以注册表与各自的 configure 为准；不为了“看起来整齐”把全部参数数据驱动化。
2. **一个领域错误出口**：新增 `_domain_error_result(error, *, prefix=None)`，统一返回 exit 2；无 prefix 时保持 `Output.failure(code, message)` 的既有中英文案，有 prefix 时保留 `<命令>: <code>: <message>` 的旧写法。四类错误（`WorkspaceError`/`GpuPublishError`/`ManifestError`/`AcceptanceRecordError`）全部改走它，原 helper 删除。
3. **一个工作区命令尾部**：新增 `_run_workspace_action(options, parser, action, *, exit_code)`，`action` 接收 options 返回报告，捕获 `WorkspaceError` 走 `_domain_error_result`，成功走 `_workspace_report`；`exit_code` 可以是整数或 `result -> int`，以保留 `advance` 的 0/3 语义。
4. **一个工作区参数骨架**：新增 `_configure_workspace_action(...)`，供 `advance`/`maintain`/`draft-fork` 使用；参数名、顺序、help 文案、required 属性全部保持，命令注册顺序不变。
5. **接口规格进测试**：新增 `tests/test_cli_command_specs.py`，锁 28 条命令的名字与顺序、三组工作区命令的关键参数、`record-online-acceptance` 的必需参数，以及四类领域错误都映射到 exit 2 且 JSON stderr 带原 code。

## 后果

- 错误映射与工作区命令尾部只有一份实现，新增一类领域错误不会再出现“少改一处”的退出码分叉。
- `--help` 输出与命令顺序由测试锁住，重构参数骨架不会悄悄改掉用户看到的东西。
- 代价：`_configure_workspace_action` 的参数组合仍是特例（version 与 change-kind 的开关），不是通用表单生成器；新增工作区命令若参数面差异大，仍应自己写 configure。
- 已知限制：测试只锁关键参数与错误码，不逐字比对完整 help；`CommandSpec` 的注册顺序仍是人工维护，新增命令要同时改注册表与测试。

## 被否决的方案

- **把 28 条命令全部数据驱动**：参数类型、互斥组、choices、required 组合差异太大，数据表会变成带大量条件分支的伪配置，help 文案也更难保持逐字不变。
- **保留四个错误 helper 只做薄委托**：名字还在，调用方仍会挑错入口；下一次新增错误类型还会再复制一份。
- **只抽参数骨架、不抽执行尾部**：三处 `try/except WorkspaceError` 仍各写一遍，退出码语义继续分散。
- **用代码生成器产出 configure/run**：生成物与手写代码混在一起，评审时要同时看模板与产物，收益低于维护成本。
