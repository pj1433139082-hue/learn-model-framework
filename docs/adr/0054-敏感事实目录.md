# ADR 0054：敏感事实目录（单一来源与三种处置）

- 状态：已接受（2026-10-21）
- 相关：ADR 0053（子智能体协作契约）、`model_lab/privacy.py`、`model_lab/distribution.py`、`model_lab/security_audit.py`、`scripts/export-model-repo.py`

## 背景

「什么算敏感事实」此前分散在三处，各写一份清单：

1. `model_lab/distribution.py` 的 `_DEFAULT_SENSITIVE_PATTERNS`：11 条，命中即整份拒绝分发，规则名用下划线（`point_code`、`platform_run`…），拒绝原因写成 `sensitive_pattern:<name>:...`。
2. `model_lab/security_audit.py` 的 `_SECRET_PATTERNS`：7 条，静态审计用，规则名用连字符（`private-key`、`github-fine-grained-token`…），正则与上面并非完全同一批。
3. `scripts/export-model-repo.py` 的 `SECRET_PATTERNS` 与 `PUBLIC_REWRITES`：导出前密钥扫描 + 公开版脱敏改写；也只有这里区分「拒绝」与「改写成占位符」。

三份清单带来两个已发生的失效：

- **同一事实三种写法**，增删一处忘另两处。厂站名只在导出脚本有词表，分发与审计都看不见；反过来，分发新增的规则审计也不会用上。
- **公开导出实测泄漏**：`--public` 靠 `TEXT_SUFFIXES` 后缀判断「是否文本」，`.js` 不在名单里，于是 `explainer/app.js` 被原样带走，公开仓里直接出现了厂站名；README 由模板生成、含模型名（厂站名），同样绕过脱敏。词表里也没有厂站名这一条。

更根本的是：清单一词表只有「名字」，没有「处置」——命中之后是整份拒绝、只报告、还是改写成占位符，每个消费方各写各的，行为无法对照。

## 决策

1. **单一目录**：新建 `model_lab/privacy.py`，每条敏感事实写成一个命名正则常量（正则字面量在全仓只出现一次），汇总为 `RULES`；一条规则是冻结 dataclass `PrivacyRule(name, pattern, scopes, disposition, replacement, note)`。
2. **三种处置（disposition）**：`block` 整份拒绝（分发拒收该文件、公开导出命中即失败）；`report` 只报告（允许留在产物里，扫描结果里提醒）；`rewrite` 脱敏改写（替换成 `replacement` 占位符后再外发）。处置写在规则上，消费方不再自行判断。
3. **消费方按 scope 取规则**：`rules_for(scope)` 返回该 scope 的规则子集，现有四个 scope——`distribution`、`audit`、`export-secrets`、`export-public`；三个消费方都改成从目录派生，禁止再持有自己的清单。
4. **规则名是契约**：`distribution` 的 11 条与 `audit` 的 7 条逐字沿用原名字与正则，`sensitive_pattern:<name>` 拒绝原因、审计输出的字符串不变；测试用「同一对象」断言锁死派生关系。
5. **公开导出按内容判文本**：能按 UTF-8 解码且前 8KB 无 NUL 即文本（不再看后缀）；脱敏只作用于 `rewrite` 规则；改写后再扫一遍，仍有 `block` 级命中就报错退出，与既有硬密钥失败同一路径。

## 后果

- 新增一条敏感事实只改一处，三个消费方自动跟上；「改了分发忘了审计」这类漂移在结构上消失。
- 处置与规则同处一行，评审时能直接看出某条规则是拒绝还是脱敏，公开导出也不必再维护第二份词表。
- 代价：`privacy.py` 成为全仓公共依赖，改一条规则要跑分发、审计、导出三套测试；scope 语义靠约定（没有运行时机制阻止消费方取别的 scope 用）。
- 已知限制：正则本身仍是启发式，误报漏报都存在（例如 `run-` 前缀的正常词会命中 `platform_run`）；厂站词表仍需人工维护（示例略）；文本判定只看前 8KB，尾部才有 NUL 的二进制文件会被当文本处理并尝试改写。

## 被否决的方案

- **维持三份清单**：即本 ADR 背景第 1 条，同一事实三写法，已出现厂站名只在导出侧、`.js` 泄漏无人发现。
- **合并成一个列表但保留三套命名与三处分发逻辑**：名字映射仍要写三遍；且没有 `disposition` 表达「拒绝 vs 报告 vs 改写」，导出侧仍需第二份词表——合并的收益被抵消。
- **给 `TEXT_SUFFIXES` 补 `.js`/`.mjs`/`.css`**：只是补掉这次实测的洞，下一个文本扩展名（`.ts`、`.vue`、无后缀脚本）还会漏；按内容判断才是可收敛的口径。
- **让 hook 拦公开导出**：守卫只覆盖少数工具调用（ADR 0048），导出脚本本来就在命令行里跑，拦不住也不解决问题。
