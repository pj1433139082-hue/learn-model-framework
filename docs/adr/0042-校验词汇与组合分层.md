# 0042 校验词汇与组合分层

- 状态：已接受
- 日期：2026-10-17

## 背景

`model_lab/manifest.py` 一度同时承担三件事：清单的纯模式/契约校验（字段形状、契约字段、运行时与环境、
版本兼容）、校验词汇（`ValidationIssue` / `ValidationCheck` / `ValidationReport`、`LifecycleState`、
`ManifestError`），以及资产记录的组合校验（artifacts/paths/digests/lifecycle/archive-status、
`point_serving` 服务契约、行为基线重放）。结果是 2000 行入口模块里塞着 1400 行校验实现。

更糟的是依赖方向倒了：`asset_validation.py` 与 `point_serving.py` 在顶层 `from model_lab.manifest import ...`，
而 `manifest._validate_loaded_document` 又 import 它们，只能靠**函数内 import** 绕开循环。于是

- 程序集内核（校验词汇）住在入口层，任何下游想用报告类型都得拖着整个 `manifest`；
- 循环依赖被藏进调用时机，静态检查抓不到，新代码很容易再制造一条；
- 记录校验与模式校验混在一个函数里，"哪些检查需要读磁盘、哪些纯看声明"无法从代码结构看出来。

## 决策

1. **词汇模块只管契约类型与共享文法**（`model_lab/check_vocabulary.py`）：`ManifestError`、`LifecycleState`、
   `ValidationIssue`、`ValidationCheck`、`ValidationReport` 逐字迁移（含 `as_dict` / `as_text` 与错误等级
   语义），并承载被两层以上共享的清单文法——`load_manifest`（装载契约：YAML/重复键/非映射一律
   `ManifestError`）、`SEMANTIC_VERSION`、`MLFLOW_EXPERIMENT`、`MLFLOW_RUN_ID`、
   `PLATFORM_DEPLOYMENT_STATUSES`，以及从报告类型派生出的 `report_identity(document)`（清单身份 = `model_id` + 生命周期状态，
   避免入口层与组合层各解析一遍）。词汇模块不含任何校验逻辑，只被依赖、不依赖上层。
2. **资产校验器是组合层**（`model_lab/asset_check.py`）：把资产记录的校验与"校验需要的外部事实"组合成一个
   `validate_asset_records(document, manifest_path) -> ValidationReport`——记录校验（lifecycle / archive-status /
   artifacts / reference digests）→ `point_serving` 服务契约 → `asset_validation` 的行为基线重放与释放快照比对，
   最后补 `_target` 角色复核提示。组合**顺序即语义**：先记录后服务、先模式后重放，记录层不通过就短路，
   不把"清单都没描述清楚"掩盖成"基线不匹配"。
3. **`manifest` 退回纯模式入口**：`validate_manifest` / `inspect_manifest` / `load_validated_asset` 公开面不变，
   但 `_validate_document` 只做结构与声明文法校验（schema_version、未知/缺失字段、形状、标量、维护状态、
   契约字段、目标、运行时、环境、版本），随后把通过纯模式校验的清单交给组合层，由组合层产出最终报告。
4. **依赖方向单向且可静态验证**：`check_vocabulary ← asset_validation / point_serving ← asset_check ← manifest`。
   `point_serving.py`、`asset_validation.py` 不再 import `manifest`；`manifest.py` 不再 import
   `point_serving` / `asset_validation`，也不再有任何函数内 import 兜底。循环依赖没有"调用时机"可藏。
5. **共享常量与共享投影只留一份，靠归属而不靠复制**：跨层共用的常量按语义归位——合法 URI 语法
   （占位段、非法字符、百分号转义、DNS 标签）归组合层（只有记录校验用）；版本文法与平台/实验标识符归
   词汇层（入口层与记录层都用）。释放快照投影 `snapshot_payload` 归记录校验层（写入方与校验方共用同一投影），
   由组合层再导出给 `manifest`，`archival` 的导入路径不变。
6. **私有名与兼容 re-export 显式化**：`manifest` 继续 re-export `LifecycleState`、`ManifestError`、
   `ValidationIssue` / `ValidationCheck` / `ValidationReport`、`ArchiveState`、`archive_state`、
   `_load_manifest`、`_pending_archive_paths`、`_redact_artifact_uri`、`snapshot_payload`，并加注释说明
   这是兼容面而非本层实现；`__all__` 显式声明公开导出，避免"下划线名字漂到下游"再变成既成事实。
7. **行为不变是这次重构的验收线**：报告类型逐字迁移、记录校验逐字迁移、调用顺序与原
   `_validate_loaded_document` 等价；判定标准是 `validate_manifest` 对全部在役资产、草稿与 fixture 的
   `ValidationReport.as_dict()` / `as_text()` 与 `load_validated_asset` 投影**逐字节一致**，
   `release-gate` 与 `validate --format json` 输出逐字节一致，而不只是"测试还绿"。

## 后果

- 词汇层 200 余行、组合层约 600 行、入口层从 2010 行降到 1304 行；入口层里只剩"看声明"的校验，
  "要读磁盘/重放行为"的校验全部可从文件名区分。
- 报告类型有了唯一归属：下游（`runtime_contract`、`release_gate`、`catalog` 等）仍可从 `manifest` 取，
  但新代码可以直接依赖 `check_vocabulary`，不必拖入入口层。
- 循环依赖变成一条可 grep 的规则：`point_serving` / `asset_validation` 出现
  `from model_lab.manifest import` 即为回退，`manifest` 出现对上层模块的 import 同理。
- 代价：多两个模块和一次组合调用；`_validate_document` 与组合层之间多一层"纯模式已通过"的隐式契约
  （组合层假定记录字段形状已校验，因此只在纯模式报告有效后才被调用）——该契约由
  `_validate_loaded_document` 的单一路径保证，并在 ADR 里钉住。

## 被否决的方案

- **只把 `ValidationIssue` 三件套挪走，其余留在 `manifest`**：循环依赖仍在，函数内 import 仍是唯一解法，
  记录校验仍与入口层耦合；这轮改动的核心收益（单向下依赖）拿不到。
- **统一收进一个更大的 `model_lab/validation/` 包代替两个模块**：包内模块可以互相 import，等于把循环依赖
  藏进包里而不是消灭它；"什么算词汇、什么算组合"失去文件级边界，下一个需求会继续往包里堆。
- **让 `asset_check` 依赖 `manifest`，用函数内 import 断开循环**：只是把旧做法换个地址，不变量仍由调用时机
  维护，静态检查与代码评审都抓不到回退。
- **共享常量两边各复制一份**（版本文法、mlflow 标识符、URI 语法）：避免新增词汇模块的最省事做法，但两份
  定义必然漂移，且漂移只会在"某个清单恰好同时触发两处"时暴露。
- **把纯模式校验作为回调注入组合层**：组合层不再自洽，调用方必须自己拼校验顺序，"先记录后服务"的语义外泄，
  新增调用点就会写出第二种顺序。
- **让 `snapshot_payload` 留在 `manifest`，`asset_validation` 函数内 import 取用**：写入方与校验方共用的投影
  回不到唯一归属，归档链路的单一事实源会被重新埋进入口层。
- **单开 `model_lab/constants.py` 只放常量**：模块数增加而职责没有提升，常量天然属于它所服务的词汇层或
  组合层，独立成模块只会制造"常量仓库"，让真正的归属继续模糊。

## 验证

- `validate_manifest` 对 49 个清单（10 个在役/样板模型、19 个草稿、20 个 fixture）以及目录形态、
  不存在清单两种错误形态（合计 51 项）的完整结论（`as_dict` / `as_text` / `load_validated_asset` 投影）
  与重构前**逐字节一致**（101314 字节，SHA-256 相同）。
- `python -m model_lab release-gate .` 输出与重构前逐字节一致（`PASSED`，9 个模型、11 个发布快照）。
- `python -m model_lab validate models/09_前馈气量-改 --format json` 结论不变（目录形态 `manifest_unreadable`
  退出码 2；`model.yaml` 形态退出码 0，输出逐字节一致）。
- 迁移代码经 AST 逐段比对确认**逐字未改**（28 个被迁移的类/函数/常量，47 个仍留在入口层的定义除两个
  入口函数外全部未变），定向测试与全量 `unittest` 全绿。
