# 架构深化验收

日期：2026-10-01。基点：`68ca67c`。范围见 [规格](../specs/2026-10-01-架构深化规格.md) 和 [设计评审](2026-10-01-架构深化评审.md)。

状态：实现与双平台全库回归完成。通用框架验收不代表真实模型部署完成。

## 交付与证据

- 路径祖先检查由 `path_safety.first_link_or_junction_component` 提供，保留各调用者的本地磁盘、外部工作区和错误分类政策。公开 CLI 测试覆盖链接/junction、原路径经过链接后含 `..`、合法外部目录及无副作用拒绝。
- ZIP 受限读取由 `bounded_archive` 提供，整包和目标成员摘要针对同份有界字节；doctor 静态检查与构建固定摘要/Linux 运行时政策仍分开。测试仅创建合成 ZIP，不使用真实公司包。
- 创建、分叉、推进和已核验 Run 与派生索引分开报告。索引 I/O 失败最多补写一次；失败保留已完成事实、退出码 2、中文说明和恢复参数。回执失败须核验同一 Run，冲突回执不覆盖，远端核验失败仍阻断。
- 恢复参数绑定已加载框架的绝对启动器。公开测试先复现裸 PATH 命令问题，再实际执行修复后的参数数组，包含空格、单引号和 `$` 字面量路径。
- 公开流写入故障测试先复现两个临时残片，再验证写入或替换失败均清理本次临时文件，不删除事实或原记录。

路径和 ZIP 的行为保持重构使用原有行为基线与新增公开入口回归；新增恢复行为和缺陷修复保留先失败、修复后通过的证据，不将基线通过描述为先失败。

## 测试边界

本次发布测试替换外部 MLflow SDK、对象存储、socket 与文件系统故障；内部计划、预检、核验及 CLI 使用真实框架实现。合成的在线证据只用于离线一致性验证，不证明真实 IoT 来源。

Linux 使用独立本地 Git clone、ext4 临时目录、Python 3.11.15 和离线缓存安装的 editable 测试环境；不修改系统 Python、代理、VPN 或旧私有模型环境。首次在 Windows 挂载盘及未安装的旧环境运行出现网络文件系统政策和隔离导入失败，不能计为通过；最终结果须在正确隔离环境复跑。

Windows 跳过项目全部在 Linux 冻结快照中实际通过：

1. `test_verified_existing_publication_survives_persistent_snapshot_failure`：仅在实际 Linux Python 3.11 执行，包括同一用例内的新上传与已有 Run 核验故障矩阵。

3. `test_workspace_rejects_symlink_ancestor`：同上；新增 Windows junction 公开 CLI 测试已实际执行。

两个平台的 doctor 均未配置真实公司包，`deployment_capability_ready=false` 是可选能力缺失，不是通用框架失败。所有这轮检查的 `remote_writes=false`；合成发布测试中的远端写入标记只记录 SDK 替身调用。

独立对抗性审查发现并处理：恢复命令误用 PATH、恢复矩阵缺少分叉/推进覆盖，以及 ZIP 中央目录低报成员大小的覆盖缺口。低报 ZIP 经 doctor 与构建入口均拒绝；不声称该用例触发框架自身的超限分支。暂存 diff 的空白检查通过。

## PR 持续集成补充

提交后的 GitHub Python 3.11 检查实际复现了环境准备缺口：旧 workflow 使用系统 `pip install -e '.[test]'`，但没有初始化 `.venv-311`；恢复启动器执行测试因此失败，其余 162 项通过。该失败不能被本地已初始化环境的通过结果覆盖。

修复只调整 CI：先通过现有 `bootstrap.sh` 初始化项目 Python 3.11 环境，并把私有目录配置定位到 runner 临时目录；随后 `doctor`、全库测试和隐私检查均使用 `model-lab.sh` 固定启动器。保留原失败用例，不修改业务代码或降低检查。GitHub 的最终结论以 PR #2 对应最新提交的检查回执为准。
