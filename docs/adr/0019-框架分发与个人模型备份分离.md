# 框架分发与个人模型备份分离

状态：已取代（superseded by [ADR 0020](./0020-历史审计证据由归档分支保存.md)，2026-10-10）

取代说明：本决策提出时以框架分发仓库为通用框架代码的唯一维护源。实测演进方向相反——个人模型备份仓库 48 次提交且持续至今（测点模式全套、公司 311 取数制品、真实 IoT 冒烟、发布门禁、19 条 ADR 均在此），框架分发仓库停在 2026-10-01 且其 `0015`/`0017` 号 ADR 只有三行摘要。ADR 0020 据此反转维护源方向：个人模型备份仓库为唯一维护源，框架分发仓库为剥离私有事实后的单向发布产物。本决策关于“避免同事 Clone 时取得真实模型源码、厂站及测点信息、训练或验证资料和发布回执”的剥离动机，以及“不删除或重写旧历史”的约束，由 ADR 0020 继续承接。

团队使用的 `learn-model-framework` 应从空仓库和全新 Git 历史建立，成为通用框架代码的唯一维护源；仅收录经逐文件审查的框架、模板、通用文档、技能和完全合成的测试资料。现有私有 `learn-model` 保留真实模型及其历史，作为模型负责人的个人云端备份，不删除或重写旧历史，也不向新仓库复制旧提交、分支、PR 或包含具体模型事实的文件。旧库中已有的框架副本只作历史记录，不再形成并行维护源。

这一边界避免同事 Clone 模板时取得真实模型源码、厂站及测点信息、训练或验证资料和发布回执；代价是框架验收必须脱离当前固定的八模型资产，私有模型工作区须经显式路径使用框架，并在新库中以合成数据验证通用能力。方案最终确认后，先撤销旧备份库的非所有者访问权，再核验新库的内容、全新历史和从零使用流程，最后给同事授权新库；此前已被 Clone 的副本不能通过撤权收回。旧库在权限收紧前不得接收新的真实模型备份推送。
